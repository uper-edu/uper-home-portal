## 页面实现

1. 顶部固定语义：记录联系为主操作；添加信息为次操作，两者继续走既有独立流程。
2. 沟通概况：最近有效人工沟通与此后有可靠时间的客户消息分栏；窄屏改为上下排列。后续未接通尝试单独呈现。人工长备注可展开，原文不翻译。
3. 全宽任务行：动作及依据、时间及状态、处理按钮与次级菜单对齐。改约执行时间与原响应截止分别显示，不互相替代。
4. 按需处理区：沿用既有草稿保护、明确选择完成任务、后续安排校验和幂等保存。
5. 时间轴：运营时区日期分组，显示 HH:mm:ss；宽屏左侧时间、中间节点、右侧内容，窄屏时间位于内容上方。每条显示来源、事件类型、操作者及原文。客户来源使用蓝色，销售记录使用克制的青绿色，系统／未知来源使用中性色，并始终配文字。
6. 历史任务及原始审计仍可展开查看；只按精确记录 ID 合并联系记录，不按相同文本去重。
7. 普通页签切换不再执行面板 `scrollIntoView`，清除旧的任务／原文定位请求，保持外层滚动位置并重置内容区到顶部。明确点击任务或原文入口仍执行定位。
8. 补齐历史自报等级枚举 `Beginner / Zero-base` 的显示映射；不改保存值或评分规则。

## 发现并修复的问题

- 原先普通页签切换强制滚动面板，旧任务／消息定位也可能在重挂载时重复执行。
- 桌面窄详情面板的任务原布局把按钮挤到时间下方，导致首行过高；改为动作、时间、操作三列，手机再折为一列。
- 次级省略号菜单原先额外显示下拉箭头，已去除重复箭头。
- 未知时间消息不得标成“此后新消息”；没有来源记录的购买信号不得假装来自客户表达。
- 两项旧渲染测试要求在默认任务卡里内嵌原文折叠，已调整为新的精确原文入口；原文定位通过浏览器复验。
- 自动化 locator 点击会预先滚动页面，曾造成额外约 100px 的测量干扰；最终使用原生点击测量页签切换，记录为 0px，未把自动化滚动误判为业务代码修复。
