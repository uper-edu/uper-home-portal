# CRM 销售效率 P0／P1 实施与验收

日期：2026-10-13。测试环境：http://127.0.0.1:4402/crm；独立 PostgreSQL 数据库 `crm_efficiency_workflow_test_20261013`。没有清空、导入或迁移 3000 客户数据，没有推送 GitHub 或部署公网。

## 已实现

- 联系结果不预选；无明确结果拒绝保存。人工尝试和接通／回复分别从有有效时间的记录投影；非联系记录、历史意向及未知时间不计为成功联系。原分类使用的字段与算法保留。
- 客户沟通语言独立于员工语言。全部 CRM WhatsApp／复制入口进入可编辑预览；未知语言必须选择，明确勾选才保存客户语言。切换员工界面语言不重写话术。停止状态禁用主动联系入口。
- 等待、培育、停止及说明原因恢复；独立复查任务，原业务任务期限不变。暂停时发送前转内部核实内容；完成／取消任务均撤销尚未发送的关联通知。复查完成要求明确选择联系安排。
- Sales 默认本人需处理、Leader 默认全部；优先级排序、个人筛选偏好和角色重置。停止／等待显示内部处理及原任务动作。列表和导出共用服务端过滤，导出真实格式为 JSON。
- 最近人工尝试与最近接通／回复使用人工原文，区分展示；保留人工备注和客户消息关联。快速表单按结果展开，支持运营日历快捷时间、明确完成任务、保存并下一位。成功后检查后续客户权限，末尾提示核对剩余待办，不宣称所有业务任务已完成。
- 缺失通知渠道记为失败，显式模拟才记为模拟。运营失败／未知发给有通知管理权限的 Leader，工作列表有异常提示。独立环境 sales／ops 映射至 CRM Bot 并保存新版本，既有通知快照不改写。
- 界面新增文案、错误提示和在线手册同步英文／印尼文／中文；姓名、人工备注和原始对话不翻译。

## 接口与数据说明

- `/api/crm/leads/:id/logs`：新增可选 `contactArrangement={state,reason,reviewAt,version}`，沿用请求ID、明确任务完成清单和消息关联。
- `/api/crm/leads/:id/contact-arrangement`：同业务事务入口，非联系调整使用 `recordKind=closure`，必须有说明、版本及合法后续安排，不计联系次数。
- 客户资料PATCH支持 `communicationLanguage`，仅允许 en/id/zh/unknown；仅改语言不改变任务负责人。
- 列表查询新增 `workScope=action|all`，返回人工联系统计；导出采用相同查询条件和数据范围，实际返回JSON。
- `contact_review` 为新增复查任务种类；新状态存于客户JSON资料，采用可选字段扩展，无批量历史客户重写。原有“暂不安排”作为待确认事项保留。
- `scripts/crm-channel-map.ts` 默认事务dry-run；`--apply` 才写新规则版本及审计。只映射引用sales／ops的Lark规则，不重写旧发送记录。运行时使用服务端DATABASE_URL。
