## 管理过程指标的准确含义

| 指标 | 口径与限制 |
|---|---|
| 未分配客户 | 当前 Owner 为空；时长从明确记录的归属变化起算。历史缺失时间显示未知，不从登记日期猜测。 |
| 首条人工联系记录 | 登记至第一条有效人工联系记录提交的自然时长中位数，包含未接通尝试；展示样本数与尚无人工记录人数。 |
| 无有效后续安排 | 活跃、未停止联系、任务信息可信且没有有效开放安排的客户。历史待确认或任务信息不可用单独列出，不算“没有任务”。 |
| 当前逾期 | 有真实期限且仍开放／逾期的任务；主值为客户数，辅助值为任务数。历史逾期事件不直接计入。 |
| 有效双向沟通 | 有有效人工“已接通／已回复”记录的客户；成功记录数及首次双向沟通时长单独显示。AI 和非联系处理不算人工沟通。 |
| 当前阶段停留 | 当前活跃阶段从明确阶段变化时间至统计时刻的自然时长中位数；已成交／关闭排除，缺失时间单列。 |

所有数字是当前筛选客户的累计记录与当前快照，并非当天绩效排名。联系与完成时间采用保存记录的服务端时间，不能当作精确通话发生时间；自然时长不能当作工作日历 SLA。逾期后已处理须有任务完成关联及可信记录时间，未知完成证据不补造。

Owner 或阶段实际变化时记录新时间；重复保存相同值不重置计时。`null` 与空字符串均表示未分配，二者切换不重置时长。历史缺失字段不批量回填。

## 营销统计口径

| 指标 | 口径 |
|---|---|
| 已登记客户 | 按首次活动归因统计去重客户记录；活动 ID 优先。历史同名活动有歧义时不重复计入。 |
| 已保存测评 | 首次归因客户中有服务端测评依据的客户，重复测评计一次；不代表参加活动。 |
| 已确认参与 | 员工确认具体活动、方式、依据、操作人及记录时间；可包含最初来自其他活动的客户。跨活动汇总计活动—客户对，不是独立人数。 |
| 已记录报名 | 首次归因客户中已记录报名状态／结果的客户；不能推断已缴费或实际入班。 |
| 登记客户报名占比 | 同一首次归因客户群的报名客户数／登记客户数；无登记客户为“不可计算”。不是营销增量效果、已缴费转化或当前筛选客户的活动转化率。 |
| 链接访问次数 | 重复打开计次，不是独立访客或二维码扫码人数；缺少独立访客分母，不再展示访客获客率。 |

登记、测评、参与、报名是独立指标，不要求逐层经过。历史布尔到场标记、试听阶段、问卷提交或测评完成不证明参与；历史标记仅作为未关联活动的原记录展示。参与可撤销，修正保留审计；撤销不删除客户或改写归因。

登记金额缺失单列；计划预算不是实际花费、登记金额不是核验收款或利润，因此 ROI 保持不可计算。活动页面按活动筛选及员工数据范围统计，不继承工作列表的临时任务筛选。公开活动接口只提供活动内容，不提供 CRM 客户统计；来源客户列表按原权限读取。

## 接口和数据变化

- 客户列表接口新增只读 `processMetrics`，在权限与筛选之后计算，列表、计数及导出仍共用既有筛选逻辑。
- 客户 profile 使用可选 `ownerChangedAt`、`stageUpdatedAt` 和 `attendanceRecords`。新增记录／实际变更记录时间，旧值不猜测回填；无需复制客户或改写评分。
- 新增 `POST /api/crm/leads/:id/attendance`：需要 `requestId`、有效活动、明确方式、确认依据及确认／撤销选择；沿用客户写入权限，事务内重新校验，操作者与时间由服务端生成。
- 同请求同内容幂等；同请求不同内容返回冲突。一次确认不创建人工联系记录、完成任务、改期或改写测评。
- `/api/crm/campaigns` 须认证，统计仅包含其可见客户；公开 `/api/campaigns` 不返回客户统计。
- Campaign 比率及 ROI 可以为 `null`，界面显示不可计算，不显示假 0%。

本轮不需要破坏性迁移或历史回填。后续本地切换应包含以上服务端与前端接口，不能仅替换静态资源。回退须保留 P0/P1 按指定任务完成及幂等安全行为。
