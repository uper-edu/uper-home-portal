# 管理界面日期与时间规范

适用于CRM、CMS、系统管理及共享管理组件。2026-10-27起作为维护要求；与[颜色与状态规范](./admin-color-system.md)共同执行。此规范不授权发布、迁移数据、修改SLA或通知策略。

## 1. 统一口径

- 页面具体时刻采用**使用者浏览器／设备当地时间（Viewer-local time）**。不根据语言、国籍、姓名、IP或客户所在地猜测时区；切换中英印界面不改变实际时刻。
- 普通时间不重复附加`Asia/Jakarta`、`America/Vancouver`、WIB、UTC偏移等后缀。正文、列表、弹层、提示、鼠标说明及无障碍名称执行同一规则。
- **运营时区（Operating timezone）属于规则配置**：工作日历、SLA、通知策略和规则模拟可以并且需要显示其配置时区。不能以精简显示为理由删除业务配置。
- 页面显示与存储分离。转换只改变读写界面的表达，不修改已保存的实际时刻、原期限、归属、通知计划或历史原文。

## 2. 三种时间数据不能混用

| 数据类型 | 示例 | 处理规则 |
|---|---|---|
| 具体时刻（Instant） | 客户约定、任务期限、实际联系、提交／接收、保存／发送／审计时间 | 先明确解析为同一时刻，再转换到当地时间显示；输入反向转换后保存 |
| 仅日期（Date-only） | 只约定“10月31日”、活动仅有日期 | 保留原日历日期，不跨日、不补午夜，不显示虚构的小时分钟 |
| 工作日历／固定时段（Operating calendar） | 雅加达周一至周六09:00–20:00 | 保留原时区与时段；不换算后覆盖为员工所在地的工作时间 |

发生时间、客户提交时间、系统接收时间、记录时间分别标明；未知发生时间不能用保存时间填补。原始对话中的“明天／下午三点”等文字保持原文，不擅自重新解释。

## 3. 格式与信息层级

- 使用24小时制。普通完整日期用`YYYY-MM-DD`；具体时刻采用`YYYY-MM-DD HH:mm`，需要追溯精确记录时保留`:ss`。展示精度不改变存储精度。
- 列表客户约定与联系时间共用当年省略年份的显示：具体时刻`MM-DD HH:mm`，仅日期`MM-DD`；跨年保留年份。具体时刻的完整记录不截断存储精度。其他紧凑列表可用`MM-DD HH:mm`；跨年或需要辨认年份时显示年份。完整时间可放入详情或鼠标说明，但不再附时区名称。
- 相对时间如“2小时前”是辅助信息；不能取代客户约定、任务执行及截止时间的具体日期和时间。不用秒级跳动干扰阅读。
- 无时间显示“未约定时间／未记录时间”，无效记录显示“时间待核对”；未知、未填写、不适用分别处理，不显示Invalid Date或猜造默认时间。
- 时间遵循现有正文／辅助信息字号和间距；关键约定不靠放大字号强调。状态色按现行颜色规范执行，新配色须单独确认。

## 4. 输入与保存

- 日期时间输入框、已保存详情、再次编辑、改期前后对比必须采用同一当地时间口径。提交具体时刻时携带明确偏移或UTC表示，不能把无偏移的本地文本直接当UTC。
- MySQL本项目DATETIME表示UTC；统一使用`crmInstant`解析，禁止在页面自行按浏览器本地时间解释数据库字符串。
- 活动现有排期以雅加达日期／时刻分字段保存。使用`campaignViewerSchedule`显示、`campaignStoredSchedule`提交；不通过本次规范重写旧活动。活动码生成时区保持不变。
- 未改时间，只保存其他字段时，原时刻、原期限及精度必须保留；不因表单只显示到分钟就截断历史秒值。
- 夏令时不存在或重复的手输时刻不能静默平移或猜选，提示选择其他明确时刻。原有带偏移记录仍按真实时刻显示，不追溯修改。
- “下个工作日”先按已配置运营日历计算，再转换成当地时间填入，销售确认完整时间后保存。

## 5. 今天、临近、逾期与筛选

- 普通具体时刻的“今天”、日期筛选、列表日期分组与当前使用者当地日期一致；列表、计数、分页和导出使用同一显示时区上下文，不能各算一套。显示上下文不能扩大数据权限。
- 具体时刻是否逾期比较真实时刻；换时区不能改变已过去多久，也不能重新计算SLA。
- 客户约定沿用已确认规则：未来24小时的具体时刻为“临近”。仅日期约定按原约定日历当天为“今天”，次日才逾期，不捏造一个截止时刻。
- 后台工作时间、SLA及通知调度继续按运营规则计算；不因员工在其他国家登录而变更。

## 6. 实现与验收

复用`src/utils/crmOperatingTime.ts`、`campaignScheduleInput.ts`及现有共享约定／任务组件；不要各页硬编码时区或拼接时区后缀。三语固定文案同步，客户姓名、原始消息和人工备注不翻译。

按影响做中文电脑端定向验收：

1. 跨日时刻在列表、详情、编辑和保存后保持同一实际时刻；表单当地时间往返无偏移。
2. 仅日期保持原日期，普通未知时间不补造；提交、接收、发生、记录时间各自清楚。
3. 修改其他字段不改变原期限；今天／筛选／导出一致。
4. 运营配置时区及工作日历不变；通知记录不重放。
5. 夏令时边界用单元测试验证，不改机器时间或业务库时间；未测设备、语言及场景如实列明。

本轮实际验证及限制见[本地验收记录](../crm/VIEWER-TIME-ACCEPTANCE.md)。维护规范不代表所有历史页面已逐一浏览器验收。
