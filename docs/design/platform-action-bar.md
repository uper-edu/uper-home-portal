# 平台设计规范 · 页底操作区

页底操作区用于完成当前页面的下一步。页面根据业务状态提供操作、金额和反馈，由共享组件决定排列、换行和底部留白。学员端以 [EnrollmentDetailActions 和 EnrollmentPriceActions](../../src/components/EnrollmentRecordLayout.tsx) 为实现参考。管理端的记录详情和弹层分别遵循[管理端记录详情规范](admin-record-detail-system.md)和[管理端表单规范](admin-form-system.md)。

## 三种布局

| 布局 | 排列 | 已验收样板 |
| --- | --- | --- |
| 有金额和明确下一步 | 金额在左，实心主操作在右。金额使用当前动作对应的业务值，适用的原价和优惠放在金额下方。预计金额明确标明。 | 班次可申请显示课程报价与「申请这个班」。待付款显示待付金额与「转账与凭证」。核验期间可补缴时显示预计剩余应付与「补缴余款」。 |
| 无金额且有明确下一步 | 手机端主操作占满可用宽度，桌面端右对齐。必要的操作提示放在按钮正上方。 | 一对一待约课的「WhatsApp 约课」。申请表和转账凭证表单也适用此布局。 |
| 仅有可选操作 | 最相关的可选操作用描边。短页贴底，长页随正文滚动。 | 凭证待核验时按条件提供「补交凭证」，并可显示客服链接。 |

当前状态没有可执行操作时，省略空底栏，让状态和说明留在正文。

「转账与凭证」页将应付金额、复制和银行信息放在正文。页底主操作随表单进度显示「提交凭证」「正在提交凭证」或「重新提交凭证」。说明保持一句，例如「财务核实足额到账后，报名才算成功」。上传失败的反馈放在凭证控件旁，便于核对文件并重试。

## 操作层级

- 同一操作区最多一个实心按钮。按钮名称描述具体动作。页面跳转使用链接，当前页提交、取消或撤回使用按钮。
- 「取消报名」「联系销售或客服」「撤回约课」用文字链接样式，放在主操作分割线上方居中。提交、撤回等当前页动作保留按钮语义，取消和撤回在实际执行前提供确认。
- 只修改一个字段的操作放在对应字段旁，例如在「偏好时段」旁放「修改」。解释操作前置条件的提示紧邻对应按钮。
- 提交期间保留按钮位置、显示进行状态并阻止重复提交。确认失败时保留可重用的输入并说明如何重试。写入结果未知时，优先查询原请求结果，避免把再次提交当作默认恢复方式。

## 窄屏与底栏安全区

- 手机端以 320 px 验证换行。按自然词界或语句换行，金额和货币符号保持可完整阅读。左右并排空间不足时，金额在上、主操作在下。按钮和文字操作的触控区域高度至少为 44 px。换行后仍保留完整名称、点击区域和可见键盘焦点。
- 固定底栏应覆盖视口宽度，底部内边距包含设备安全区。正文使用底栏的实际渲染高度加正文间距作为底部留白。底栏高度已经包含安全区时，正文只计入一次。文案换行、字体缩放和视口变化后，最后一项正文或表单字段仍可滚动到栏上方。
- 软键盘展开时，聚焦字段和校验信息仍可滚动到可见处。键盘关闭后恢复底栏位置和安全区留白。只有可选操作的页面使用随正文布局，避免固定栏持续占据阅读空间。

## 验收要点

用目标场景核对实心、描边和文字操作的顺序、点击区域与键盘焦点。窄屏检查长文案是否完整、页面是否横向溢出及最后一个控件能否滚到固定栏上方。表单用模拟响应确认提交中、重复触发、失败重试和成功后的落点。设备安全区和软键盘使用真机验证，浏览器缩小视口只验证布局及滚动。
