# 管理工作区表单规范

适用于CRM、CMS及系统管理的新建或明确调整的表单。采用全局4／8／12／16／24／32px间距阶梯；共享变量定义于`src/components/admin-form.css`。本轮按[表单盘点](./ADMIN-FORM-INVENTORY.md)分批接入；不影响公开问卷、聊天、HSK测评及只读列表。

| 层级 | 间距 | 共享变量 |
|---|---:|---|
| 区域标题行下边缘至第一个字段 | 8px | `--admin-form-panel-top` |
| 字段名称至输入／选择控件 | 8px | `--admin-form-label-gap` |
| 相邻字段或字段行 | 12px | `--admin-form-field-gap` |
| 控件至所属辅助说明／错误提示 | 4px | `--admin-form-help-gap` |
| 不同业务子组，例如原约定处理与替代约定 | 16px | `--admin-form-group-gap` |
| 最后一个字段或所属说明至本区底部分隔线 | 16px | `--admin-form-panel-bottom` |
| 双列字段横向间距 | 16px | `--admin-form-column-gap` |

- 容器统一控制字段之间的间距。字段本身清零重复上下外边距，不叠加历史margin与容器gap；子组仅保留明确的组间差额。
- 名称、控件及所属说明视为一个字段组。说明紧跟字段，不作为另一个普通字段占12px间距；没有说明时不渲染空段落。
- 子组标题至首字段沿用8px；子组内部字段仍用12px。复选框等条件内容保留原有控件高度及校验，不因间距统一改变交互。
- 同层级对齐，不强求不同内容等高。长原文／多行名称自然换行，不能裁掉内容或缩小字号、行高和操作高度来压缩。
- 正文、辅助文字、主题颜色、时间格式及权限执行现有规范；不改变草稿、保存事务、数据、任务期限或通知策略。
- 代码共用变量，固定文案EN／ID／ZH同步。验收按本次授权范围，中文PC实测字段边界和实际间隔，报告其他语言／设备未测状态。

英文对照：label gap、field gap、help gap、group gap、column gap。
印尼文对照：jarak label、jarak kolom isian、jarak keterangan、jarak kelompok、jarak antarkolom。


## 字段、分区与动作

- 字段（Field）复用`AdminField`：标签14px／1.6、普通输入14px／1.6、所属辅助说明13px／1.6。原文输入可使用已明确的15px正文变体；不以缩小字号压缩长内容。
- 标签与控件关联；必填使用星号和可访问属性，选填不重复加后缀。复选／单选保持独立紧凑选项，不套用普通输入的宽高。
- 分区（Section）用`AdminFormSection`：同级标题14px／1.6、600字重；浅中性标题背景仅用于同级卡片，普通分区用中性细线。无业务状态含义的分区不使用警告／危险底色。
- 四区等需要收起的内容保留既有受控折叠组件；保持挂载和草稿。标题行放展开、简短摘要及清除操作；清除是独立按钮，不与展开按钮嵌套。
- 操作区（Actions）复用`AdminFormActions`，按钮至少40px，动作间8px；同一保存范围一个主操作。查询结果、恢复、撤销会话、上传及删除不得包装成普通“保存”。
- 反馈（Feedback）复用`AdminFormFeedback`：未保存中性、保存中蓝、确认保存成功绿色、明确失败红、结果未知琥珀；保留文字，不靠颜色表达。不能把“请求发出”当作已保存，不能仅因异常就声明“未写入”。

## 弹窗／抽屉（Modal / Drawer）

编辑壳统一为固定标题、单一正文滚动区域、固定底部操作，桌面正文内边距24px；不叠加外壳与正文padding，不让保存按钮滚出视口。保留父组件的未保存确认、权限、版本及结果查询；布局组件不持有业务值或发起写入。

标题唯一。响应式编辑器的必填说明与标题同行、垂直居中，横向间距 12px，空间不足时自然换行。推广活动与普通 CMS 表单沿用居中弹窗，系统用户、角色和需录入多组信息的表单可用右侧抽屉。新接入的管理端编辑器默认复用 `AdminEditor`，由页面按用途选择容器。特殊业务布局沿用 `AdminDialog` 管理背景交互、页面滚动、键盘焦点及关闭。独立记录工作区继续遵循记录详情规范。

「管理凭证」使用共享居中弹窗，标题下显示当前账号或集成，正文显示状态、录入字段和操作结果，底栏保留当前步骤的主要操作。打开时聚焦标题，进入录入步骤时聚焦第一个凭证字段，关闭时回到入口。发件账号编辑和 Lark 应用设置等多字段业务配置沿用抽屉。

### 响应式表单布局

- 长表单使用 `AdminFormSection` 按业务分区。成对短字段由 `AdminFormGrid` 排版，按实际内容宽度切换。达到 560px 使用两列，窄于 560px 使用一列。两列之间使用 16px 的共享间距，DOM 阅读与键盘顺序相同。
- 长名称、URL、原文和多行编辑框使用整行。置于网格中的全宽字段显式标记 `data-admin-full-width`。独立的短表单和长内容分区可直接使用单列。按字段语义决定配对，例如「课次／每课次分钟数」和「比例上限／金额上限」。
- 在 `AdminEditor` 上使用 `responsiveForm` 接入长表单样式。抽屉最大宽度 780px，标题和底栏固定。字段、权限、草稿、提交和回执由原页面处理。右侧新建和编辑抽屉的分组与操作区采用下方规则。
- 首批样板为班次新建及编辑、课程报价和 CMS「精选热门项目」。存量页面分批接入。验收同时核对宽窄屏排列、横向溢出、阅读与焦点顺序、底栏以及原有校验和提交内容。

### 右侧编辑抽屉的分组、缩进和操作区

以 CRM「报名班次 → 创建班次」为样板。使用 `AdminEditor` 的 `drawer` 和 `responsiveForm`，正文按填写顺序排列业务分组。

- 用 `data-admin-section-stack="open"` 包裹同级 `AdminFormSection variant="subgroup"`。组标题与正文的起始边缘对齐，组内字段整体缩进。分组容器内容宽度达到 568px 时，字段区起始端缩进 8px。窄于 568px 时取消缩进。同级组之间留 24px，由共享样式统一控制。开放式分组用标题和留白区分，细线只放在固定的头栏和底栏。
- 字段区以缩进后的实际网格宽度决定列数。达到 560px 使用两列，按从左到右的阅读顺序排列。更窄时自动改为单列，与键盘顺序一致。两个短字段可以并排，长原文、多行编辑或复杂控件可以占整行。范围明确的小整数可以用 `AdminSingleSelect`，编辑既有记录时保留已保存的合法值。
- 标签和占位文字承担基本指引。空白新表单省去逐字段重复提示。字段输入有误时就近说明如何修正，保存不可用时在底栏按钮上方给出首项可处理原因。草稿保存与发布分别沿用各自校验。模板更新、权限限制等影响操作的信息放在相关字段或区块旁。
- 固定底栏使用 `AdminFormActions`，右对齐排列「取消 → 有需要的次操作 → 主操作」，间距沿用共享的 8px。每个保存范围只有一个强调按钮。主操作使用具体动词，如「保存草稿」「保存修改」或「发布」。班次样板为「取消 → 学员预览 → 保存草稿」。宽度不足时自然换行，保持顺序及右对齐。保存中拦截重复提交，结果未知时以「查询保存结果」替代可能重复写入的保存操作。
- 右上角的叉是「关闭」，与底栏「取消」和 Esc 共用同一关闭流程。下拉或嵌套弹窗开启时，由最上层界面先处理 Esc。有未保存修改时请求确认，继续编辑保留草稿。关闭后焦点返回打开抽屉的入口。点击区、图标尺寸和忙碌保护沿用下方规则。

实现参考 [班次抽屉](../../src/components/crm/CrmEnrollmentClasses.tsx)、[共享编辑器](../../src/components/admin/AdminEditor.tsx)、[共享表单布局](../../src/components/AdminFormLayout.tsx)及[分组与网格样式](../../src/components/admin-form-layout.css)。

普通编辑打开后聚焦标题。抽屉和弹窗的右上角关闭按钮由 `AdminEditor` 管理。桌面点击区为 40 × 40 px，窄屏为 44 × 44 px，20 × 20 px 叉图标在点击区水平、垂直居中。按钮和标题区域在同一行垂直对齐。页面通用按钮样式需排除该控件，避免覆盖间距、边框和焦点样式。验收以实际渲染的图标和按钮两者的中心为准，覆盖系统管理、CRM 和 CMS 的代表性编辑器。

放弃编辑或执行不可逆操作前使用 `AdminConfirmation`，默认聚焦取消。嵌套确认关闭时回到编辑器触发位置，整个编辑器关闭时回到原页面入口。关闭按钮与 Esc 共用页面定义的关闭判断，忙碌时保留关闭保护。只有已有业务允许时才支持点击背景关闭。

短成功反馈可以用 `AdminFormFeedback` 的浮层放置，避免挤动列表。需要用户处理的失败、字段错误和待查询结果留在相应编辑器中；查询与重试使用业务原有机制。

各区收起保留草稿。明确失败保留可修正输入。结果待确认时保留原提交和草稿，优先查询原请求，明确区分暂未查到、查询失败和已确认。旧接口缺少回执查询时，就地核对原记录。仅确认记录内容一致时说明已核对到的事实。主题切换保留待确认状态，危险操作使用共享确认并说明受影响对象。

## 适配与验证

接入采用显式`data-admin-form`、字段组件及分区／操作组件，不使用全站裸`label/input/textarea`选择器。主题色执行颜色规范；具体时刻及输入执行时间规范。保留原始文本、三语文案、各自保存范围、草稿、权限与业务规则。

本轮以中文电脑端选择各类代表样本，验证字段、必填、分区、滚动、关闭／保留草稿和关键操作；高风险写入不因界面适配而执行。三语默认文字自动检查不等于英文／印尼文实屏通过；窄屏能力保留，本轮未专项验证。


## CRM业务分区及适用方式

本轮CRM续批使用`CrmFormSection`为共享分区提供明确的业务标题，不持有表单状态、不发请求。各族的分区与入口见[盘点](./ADMIN-FORM-INVENTORY.md)。

- 客户修改按“当前上下文→本次修改→依据→结果／操作”组织；原始记录与本次新增内容分开，不能改写原记录。
- 活动基本信息直接显示，补充资料按主题折叠，保持内容挂载。来源核实先保留依据和作用范围，再选择归因处理。
- 运营页面沿用按主题保存的吸顶标题，不再把单个配置组挤在半幅卡片。通知策略及渠道保留各自的编辑对象和保存动作；跨主题保留草稿，关闭或替换已修改对象前确认。
- 普通分区使用中性细线和统一标题；不得同时叠加分区边框、旧子组分隔线、父容器gap与兄弟margin。无字段的空容器不留占位。
- 页面配置、独立抽屉、居中弹窗、短内联操作和身份比较宽页是不同容器用途，不强行全部改成弹窗。短出席记录不为统一而增加冗余标题。
- 共享分区标题注册`data-admin-section-title`，运营旧的去重规则不得将其隐藏。不能用“节点存在”替代实际可见验证。
- 折叠本身不提交、不清空、不改变条件必填。关闭确认只作用于未保存输入；保存中保留禁用反馈，结果未知继续原有查询流程，不能包装成成功或改写保存范围。

## 配置页面的查看、编辑和生效

- **普通设置**可直接在页内编辑。销售运营策略、报名规则和招生邮件加载后直接显示可编辑字段，按当前主题或配置组保存。
- **核验后生效**将当前生效值放在摘要，候选值放在编辑器。主操作写「测试并保存」或业务明确的等价动作。校验进度、分项失败、冲突和结果查询放在操作所属区域。仅在实际执行后展示结果，不为按钮或结果占位。
- **独立状态动作**显示当前状态，使用「开启外发」「暂停外发」「发布」等动词。需要确认的动作使用共享确认弹窗，说明范围和影响。没有其他可编辑项时无需常驻保存按钮。
- **凭证与绑定**在摘要中显示配置状态，短凭证操作使用共享居中弹窗。保留绑定、核验、撤销及候选启用的业务和权限边界。浏览器草稿只保存非密钥字段。
- **记录配置**沿用共享列表＋详情与单条编辑流程。列表筛选、发送记录及审计仅用于浏览。账号、发信池、通知规则、班型模板等各按独立记录提交，保持各自的权限及回执。
- **刷新与访问撤销**使用共享读取状态。刷新保留最后一次成功读取的记录和筛选；失败时提示需要重试，并阻止依赖最新数据的编辑。访问失效时清除旧记录并收起操作。数量只显示已读取的统计。自动带入的初始数据属于新记录的初始值，首次人工改动才触发未保存提醒。

对照「集成配置」中的 AI 模型服务、Lark 应用和 Google Analytics。AI 模型服务直接编辑当前生效值，修改通过主备模型测试后才保存；凭证和当前配置诊断各自操作。走查时区分当前值、草稿和结果待确认。关闭或切换时保护草稿，失败时保留可修正输入，网络结果不明时读取原操作或核对已保存配置，避免自动重复提交。既有工作区按[配置页面盘点](./ADMIN-FORM-INVENTORY.md)核对。

### 配置字段的依赖、继承与默认值

- **按填写顺序组织。** 先放决定后续配置的字段。前置条件未满足时，尚无法判断是否适用的整组内容可以暂缓显示。已知适用、需等待其他输入的控件保留标签并禁用，在确有需要时简短提示如何解锁。字段的可见性、可编辑状态、条件必填和提交校验共同遵循业务规则。
- **集中展示继承值。** 用 `AdminFormSummary` 把模板或上游记录带入的关键值放在同一只读区域，紧跟来源字段。摘要使用「标签＋值」，保持名称和口径清晰。日常可编辑的字段放在对应业务分组。
- **可编辑默认值直接填入控件。** 只要仍在使用默认值，变更上游后就更新它。用户明确修改的值随草稿保留，保存并重开时也采用该值。上游变化造成冲突时就近提示，仍有效的内容继续保留。需要清除一组已填日期或课表时，先说明影响并用共享确认弹窗提供取消。
- **让可选操作靠近它影响的内容。** 一个复选框即可控制后续输入时，直接显示复选框。低频且包含多个相关操作的内容可用 `AdminDisclosure`。计算结果紧随对应输入，收起内容后仍应保留需要随时核对的结果。控件选型见[共享组件与控件](admin-list-controls.md#配置表单的共享组件与控件)。

### 创建班次样板

| 分组 | 输入、依赖与呈现 |
| --- | --- |
| 班型与课程 | 选择班型模板后开放后续分组。根据模板及绑定课程集中展示课程、总节数、每节分钟数、报名总价、教师类型、人数下限、人数上限和适用的标准总价。使用「人数下限（到账为准）」表示达到开班条件所需的足额到账人数。使用「人数上限」表示班次容量。 |
| 授课安排 | 教师与每次上课节数在桌面同排。按模板教师类型提供在职教师选项。切换模板时保留匹配的教师，清除不匹配的教师并提示。新建时节数默认 1，可选 1–4。编辑时回显已有的合法节数。 |
| 排课 | 按班次时区和上课日类型设置首课与每周上课日。首课决定默认开始时间。直接显示分日设置复选框，新建时默认未勾选。勾选后显示各上课日的时间，首课对应星期继续跟随首课时间。停课区默认折叠，已选日期紧邻日历按钮。「预计结课」放在停课区之后，随日期增删更新。 |
| 自助报名 | 报名截止可直接选择日期和时分。首课日期确定后，默认班次当地当天 `00:00`。手动修改后，变更首课日期或保存并重开草稿均保留手动值。 |

班次抽屉底栏按「取消 → 学员预览 → 保存草稿」排列。草稿允许教师未分配，发布需要已选教师并通过班次校验。验收分别检查模板改选、日期限制、默认值联动和手动值保留，再检查固定底栏、关闭回焦与草稿保护。[班次抽屉实现](../../src/components/crm/CrmEnrollmentClasses.tsx) · [日期与时间输入规范](admin-time-system.md#4-输入与保存)
