# 管理工作区表单规范

适用于CRM、CMS及系统管理的新建或明确调整的表单。采用全局4／8／12／16／24／32px间距阶梯；共享变量定义于`src/components/admin-form.css`。本轮按[表单盘点](./ADMIN-FORM-INVENTORY.md)分批接入；不影响公开问卷、聊天、HSK测评及只读列表。

| 层级 | 间距 | 共享变量 |
|---|---:|---|
| 区域标题行下边缘至第一个字段 | 8px | `--admin-form-panel-top` |
| 字段名称至输入／选择控件 | 8px | `--admin-form-label-gap` |
| 相邻字段或字段行 | 12px | `--admin-form-field-gap` |
| 控件至所属辅助说明／错误提示 | 4px | `--admin-form-help-gap` |
| 不同业务子组，例如原约定处理与替代约定 | 16px | `--admin-form-group-gap` |
| 最后一个字段或所属说明至本区底部分隔线 | 16px | `--admin-form-panel-bottom` |
| 双列字段横向间距 | 16px | `--admin-form-column-gap` |

- 容器统一控制字段之间的间距。字段本身清零重复上下外边距，不叠加历史margin与容器gap；子组仅保留明确的组间差额。
- 名称、控件及所属说明视为一个字段组。说明紧跟字段，不作为另一个普通字段占12px间距；没有说明时不渲染空段落。
- 子组标题至首字段沿用8px；子组内部字段仍用12px。复选框等条件内容保留原有控件高度及校验，不因间距统一改变交互。
- 同层级对齐，不强求不同内容等高。长原文／多行名称自然换行，不能裁掉内容或缩小字号、行高和操作高度来压缩。
- 正文、辅助文字、主题颜色、时间格式及权限执行现有规范；不改变草稿、保存事务、数据、任务期限或通知策略。
- 代码共用变量，固定文案EN／ID／ZH同步。验收按本次授权范围，中文PC实测字段边界和实际间隔，报告其他语言／设备未测状态。

英文对照：label gap、field gap、help gap、group gap、column gap。
印尼文对照：jarak label、jarak kolom isian、jarak keterangan、jarak kelompok、jarak antarkolom。


## 字段、分区与动作

- 字段（Field）复用`AdminField`：标签14px／1.6、普通输入14px／1.6、所属辅助说明13px／1.6。原文输入可使用已明确的15px正文变体；不以缩小字号压缩长内容。
- 标签与控件关联；必填使用星号和可访问属性，选填不重复加后缀。复选／单选保持独立紧凑选项，不套用普通输入的宽高。
- 分区（Section）用`AdminFormSection`：同级标题14px／1.6、600字重；浅中性标题背景仅用于同级卡片，普通分区用中性细线。无业务状态含义的分区不使用警告／危险底色。
- 四区等需要收起的内容保留既有受控折叠组件；保持挂载和草稿。标题行放展开、简短摘要及清除操作；清除是独立按钮，不与展开按钮嵌套。
- 操作区（Actions）复用`AdminFormActions`，按钮至少40px，动作间8px；同一保存范围一个主操作。查询结果、恢复、撤销会话、上传及删除不得包装成普通“保存”。
- 反馈（Feedback）复用`AdminFormFeedback`：未保存中性、保存中蓝、确认保存成功绿色、明确失败红、结果未知琥珀；保留文字，不靠颜色表达。不能把“请求发出”当作已保存，不能仅因异常就声明“未写入”。

## 弹窗／抽屉（Modal / Drawer）

编辑壳统一为固定标题、单一正文滚动区域、固定底部操作，桌面正文内边距24px；不叠加外壳与正文padding，不让保存按钮滚出视口。保留父组件的未保存确认、权限、版本及结果查询；布局组件不持有业务值或发起写入。

标题唯一，必填说明附标题，不额外占行。长内容自然滚动；键盘焦点限制在当前操作层，关闭回到原入口，页面滚动与焦点恢复。原生CRM dialog保留自身生命周期；CMS自定义编辑器使用`useAdminEditorFocus`，嵌套确认框独立处理Escape和焦点。

各区收起不等于清除。失败保留输入；未知结果沿用已存在的查询机制，不新增盲目重提。没有查询能力的旧接口如实列入限制，不以通用组件掩盖。

## 适配与验证

接入采用显式`data-admin-form`、字段组件及分区／操作组件，不使用全站裸`label/input/textarea`选择器。主题色执行颜色规范；具体时刻及输入执行时间规范。保留原始文本、三语文案、各自保存范围、草稿、权限与业务规则。

本轮以中文电脑端选择各类代表样本，验证字段、必填、分区、滚动、关闭／保留草稿和关键操作；高风险写入不因界面适配而执行。三语默认文字自动检查不等于英文／印尼文实屏通过；窄屏能力保留，本轮未专项验证。


## CRM业务分区及适用方式

本轮CRM续批使用`CrmFormSection`为共享分区提供明确的业务标题，不持有表单状态、不发请求。各族的分区与入口见[盘点](./ADMIN-FORM-INVENTORY.md)。

- 客户修改按“当前上下文→本次修改→依据→结果／操作”组织；原始记录与本次新增内容分开，不能改写原记录。
- 活动基本信息直接显示，补充资料按主题折叠，保持内容挂载。来源核实先保留依据和作用范围，再选择归因处理。
- 运营页面沿用按主题保存的吸顶标题，不再把单个配置组挤在半幅卡片。通知策略及渠道保留各自的编辑对象和保存动作；跨主题保留草稿，关闭或替换已修改对象前确认。
- 普通分区使用中性细线和统一标题；不得同时叠加分区边框、旧子组分隔线、父容器gap与兄弟margin。无字段的空容器不留占位。
- 页面配置、独立抽屉、居中弹窗、短内联操作和身份比较宽页是不同容器用途，不强行全部改成弹窗。短出席记录不为统一而增加冗余标题。
- 共享分区标题注册`data-admin-section-title`，运营旧的去重规则不得将其隐藏。不能用“节点存在”替代实际可见验证。
- 折叠本身不提交、不清空、不改变条件必填。关闭确认只作用于未保存输入；保存中保留禁用反馈，结果未知继续原有查询流程，不能包装成成功或改写保存范围。
