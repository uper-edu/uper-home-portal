# 管理端搜索、下拉和内容页签规范

适用范围为 CRM、CMS 和系统管理。以 CRM 客户页和「创建班次」抽屉为参考。课程报名等公开页面沿用公开站设计。语言切换、行内动作菜单、列表快捷筛选和全局导航沿用各自的交互语义。

## 页面刷新

- 页面级「刷新」放在标题区右侧的操作组，和标题同一行。操作组从左到右依次为其他次要操作、「刷新」、主操作。没有主操作时，「刷新」放在操作组最右侧。新增和编辑等主操作沿用原有权限。
- 搜索、筛选和分页放在各自的控件区。标题区空间不足时，操作组整体换到标题下方，组内顺序保持一致。刷新仅作用于当前页面内容或已选中的子视图。
- 刷新使用共享 `AdminRefreshAction` 次要按钮（基于 [`AdminPageAction`](../../src/components/admin/AdminPageAction.tsx)），默认显示刷新图标和文字。执行中显示忙碌状态、防止重复请求，并保留键盘焦点。刷新后保留搜索、筛选、排序、页码和滚动位置。存在未保存草稿时，沿用页面的草稿保护。
- 页面仅在读取失败时需要重新请求的，使用错误状态旁的「重试」。若多个独立区块确实可以单独刷新，各自的刷新入口放在对应区块标题右侧，并明确作用范围。

## 搜索框

- 统一使用 `AdminSearchField`。`CrmListSearch` 和 `CrmRecordSearch` 分别提供列表布局和记录侧栏的接入方式，复用同一个输入控件。
- 高 40px，圆角 10px，文字 13px、行高 20px，左侧放 16px 搜索图标。正文、提示文字、边框、背景与焦点使用管理端语义色。焦点要在深浅色下清晰可见。页面可定宽和换行，控件外观由组件维护。
- 保留可访问的控件名称。占位文字按实际匹配字段写；搜索词和清除条件的结果由业务列表管理。即时搜索继续沿用现有防抖、分页和权限逻辑，避免旧结果覆盖新查询；进入详情和返回时按页面原有规则保留筛选与位置。

## 下拉

- 管理选项统一使用 [`AdminSingleSelect`](../../src/components/admin/AdminSingleSelect.tsx)。CRM 的 `CrmSelect` 包装器负责转换选项。固定枚举、筛选、可搜索选项和多选共用触发器、浮层及选项结构。短枚举直接展开，长列表按需启用选项搜索。
- 常规触发器高 40px，圆角 10px；触发项与选项文字 13px、行高 20px，普通选项最小高 36px。选中项使用浅色底和勾选标记，多选用复选框。选项允许换行。附说明的选项在标题下展示说明，按内容增加高度。普通、选中、禁用、悬停和键盘焦点使用共享语义色和样式。
- 浮层贴合触发器，容纳在屏幕内；长选项列表内部滚动，不能撑高工具栏或把正文下推。首次展开定位到搜索框、当前可用选项或首个可用选项。方向键移动，Home／End 跳至首末，跳过禁用项；单选提交后关闭，多选继续选，Esc 关闭并还原焦点。Tab 离开后继续表单顺序，点击外部关闭时保留用户点击位置。查询无结果时显示明确提示。即时筛选无需额外提交。
- 业务决定字段值、排序、可见项、禁用原因以及筛选范围。控件负责展示和键盘行为。权限及保存仍由服务端校验。
- 配置表单的下拉应有稳定默认顺序。分类有业务含义时先按分类排序，同类再按名称自然排序，名称相同用稳定标识区分先后。有对应管理列表时，表单选择器复用同语义的默认顺序。例如班型模板列表与「创建班次」下拉共用「HSK 级别 → 班型 → 教师类型 → 名称」。创建班次按报名业务筛选可用模板。 [班型模板排序实现](../../src/utils/enrollmentTemplates.ts)
- 工作区通用按钮样式需排除共享下拉的触发器和选项。验收直接进入目标页面并展开下拉，检查普通选项为无独立边框的列表行，选中项显示浅色底和勾选，以及 Esc 关闭后回焦。

## 配置表单的共享组件与控件

| 使用场景 | 共享实现 | 页面负责 |
| --- | --- | --- |

| 字段标签、必填与条件输入 | `AdminField`、`AdminFieldLabel` | 何时显示、解锁、标为必填或提示错误 |
| 枚举、关联记录、每周上课日 | `AdminSingleSelect` | 选项范围、默认顺序、单选或多选、依赖变化后的取值 |
| 单日期、日期与时间、仅时间 | `AdminDateField`、`AdminTimeField` | 时区、可用日期、默认值、联动和校验 |
| 需标注或多选的日期 | `AdminCalendarPicker` | 日期标记、可选范围及选中后的业务结果 |
| 单项固定值、成组继承值 | `AdminStaticField`、`AdminFormSummary` | 标签、值和口径 |
| 可选条件、低频分组 | `AdminField` 内的复选框、`AdminDisclosure` | 条件字段的启用规则和低频分组内容 |
| 底栏、确认、保存反馈 | `AdminFormActions`、`AdminConfirmation`、`AdminFormFeedback` | 动作层级、草稿保护、受影响对象与回执处理 |

## 内容区页签

- 同一页面的内容切换用 `AdminDetailTabs`；可直接访问的子页面用 `AdminContentNav`。两者共享样式。客户详情用前者，报名管理和收款核验用后者。
- 桌面文字 14px，最小高 48px。选中时显示 3px 品牌色底线、浅色底和加粗文字。图标有助识别时保留现有图标。不为凑齐版式强制加图标。窄屏允许两列换行，标签保持可读。
- 页内切换使用 tablist／tab／tabpanel，当前页签进入 Tab 顺序；左右方向键和 Home／End 切换，沿用详情的草稿与焦点保护。链接型导航用普通链接和 `aria-current`，保留直达、刷新、浏览器返回及打开新标签页。普通点击在当前工作区内切换，只更新页签下方的内容，标题和页签位置保持稳定，遵守草稿保护。
- 经营看板等需要并列展示多项主题的工作区，可用 `AdminTopicFrame` 搭配 `AdminContentNav` 的目录布局。桌面左侧目录沿用 256 px 宽度和吸顶规则，选中线移至行首；低于 1024 px 改用可展开目录，让正文占满可用宽度。

## 列表中的记录入口、操作和状态

- 记录首列用 `AdminRecordEntry`，行内次要操作用 `AdminRowAction`。有直达地址时渲染链接。打开当前页操作层或执行动作时渲染按钮。统一使用管理端操作色、默认轻下划线、悬停强调和独立的键盘轮廓。记录名可加粗，操作使用明确动词。
- 表格及有多项操作的工作列表只让记录名称和明确操作响应点击。仅有一个去向的侧栏行可整行点击，当前项保留浅色底、选中边线和可访问标记。
- 状态保持可读的文字和既有语义色。需要查看进度时加明确的业务入口。危险操作、身份待核实、带权限或前置条件的流程继续使用各自的业务组件。组件样式不改变业务权限、状态口径或保存行为。
- 记录入口和行内动作规则适用于所有管理列表。客户款项和其他多操作表格的空白单元格保持被动；CMS 与系统管理的多动作卡片用显式的「编辑」等入口。包含时间或状态的行内入口只突出操作名称，元信息沿用原语义色。

## 原文与证据入口

- 在记录摘要中，时间、来源名称和联系结果用正常可读文字。能打开原始记录时提供明确的「查看原文」，使用 `AdminRowAction`。明确结果保持 `CrmContactResult` 的语义色。找不到可验证的原始记录时，来源仍作为只读信息显示。
- 保留 `CrmEvidenceAction` 表达按来源定位、展开和打开完整记录的业务语义。就地展开复用共享 disclosure，使用专有 `aria-expanded` 与焦点，不写成页面跳转。
- 推广来源异常的「来源依据」是可见范围内的只读展开。核实动作仅在有核实权限时显示。授权仍以服务端为准；从原文或核实界面返回时恢复相应触发控件的焦点。

## 次要操作与复制

- 高频任务直接显示文字操作。一个次要操作直接呈现，多个次要操作使用 `AdminSecondaryActions`。按权限和当前状态组装操作后再决定呈现方式。菜单可用键盘进入，Esc 可关闭；从菜单发起确认时，退出确认回到「更多操作」。危险动作仍由原确认流程判断和执行。
- 页头的「更多操作」使用共享图标按钮的页头样式。按钮为 44 × 44 px，圆角 12 px，使用管理端边框色，三点图标水平与垂直居中。表格行和字段旁使用无可见边框的紧凑图标按钮。两种样式均保留可见的键盘焦点。
- 复制使用 `AdminCopyAction`。图标置于字段右侧，默认无边框和背景，名称说明复制的内容。结果在触发位置附近短暂显示，页面与卡片位置保持稳定。剪贴板不可用时，原值仍可选中并手动复制。复制只写剪贴板。
- 进展与推广链接保存成功使用共享浮层反馈。需要用户核对的保存失败或结果待确认留在相应的操作区。沿用各自的保存、请求查询及授权规则。

## 表格、分页与列表状态

- 表格统一使用 `AdminListTable`。表头注明作用范围，金额和数量可右对齐，已排序列提供 `aria-sort`。宽表在列表容器内横向滚动。各业务仍决定列、查询范围、排序口径和操作权限。
- 用 `AdminListState` 区分首次加载、无匹配记录、读取失败及无权限。刷新时可保留同一授权范围的记录，并标记正在更新。收到权限拒绝后清除旧记录。仅在失败状态显示重试。
- 用 `AdminListPagination` 展示和切换页码。筛选和排序改变时从第一页开始。返回班次列表恢复筛选、排序、页码、滚动和入口焦点。打开客户款项时保留清单筛选和页码。通知发送记录在服务端返回的最近 200 条内按状态筛选，每页 25 条。指定发送记录的链接仍直达该条记录。
- 首轮接入「报名管理 → 班次」与名单、「收款核验 → 客户款项」及「销售运营 → 发送记录」。

## 共享组件命名

- 跨 CRM、CMS、系统管理的组件按使用目的取名并加 `Admin` 前缀，例如 `AdminRecordEntry`、`AdminRowAction`、`AdminRecordHeader`。新增组件放在 `src/components/admin/`。已登记的共享实现继续从原入口复用，例如 `AdminForm` 以及 `AdminFormLayout.tsx` 中的表单布局组件。
- 组件依赖 CRM 的业务语义、状态或权限时，使用相应域名前缀，如 `CrmProgressAction` 或 `CrmEnrollmentFinance`。公开站共享控件沿用 `Public` 前缀。
- 有旧前缀的共享控件随实际改造逐步迁移。代码迁移时先核对调用方、样式和测试；同一个行为仅维护一套实现。

## 入口核对

| 区域 | 本轮核对入口 |
| --- | --- |
| 客户与商机 | 客户工作列表、字段表、客户与商机侧栏、商机列表、客户详情的历史搜索及内容页签 |
| 报名与财务 | 班次列表及侧栏、售后订单、客户款项、课程报名核款、两组内容导航 |
| 推广及销售运营 | 活动列表及侧栏、推广异常、通知列表和运营表单的选项控件 |
| 系统文档、CMS、系统管理 | 文档检索、CMS 当前分类搜索及伙伴分类、系统用户搜索及 Lark 查询方式 |

验收对照客户基准检查实际渲染的字体、尺寸、语义色和焦点，至少验证选中项、无结果、单选和多选键盘路径、抽屉内弹层，以及链接型和页内页签各自的导航行为。

客户字段表的初始列与恢复默认共用同一字段顺序。统计下钻标签与统计卡使用相同的时长区间文案，区间端点跟随现有计算口径。
