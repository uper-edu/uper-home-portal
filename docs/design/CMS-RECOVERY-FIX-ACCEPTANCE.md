# CMS原请求恢复：修复及验收

最后更新：2026-10-28T17:13:54-07:00（America/Vancouver）。仅本地实施；未推送、发布或更新禅道。本轮控制在CMS恢复闭环，不扩展其他CMS功能。

## 实现

- 查询明确返回not_found后，允许用户点击“重试原请求”。保留原操作人、请求ID、集合、冻结内容和原版本；不自动重发或产生新ID。失败／未知继续保留，明确4xx拒绝保留草稿并解除在途锁定。
- 图片上传增加20秒超时；超时转为结果未确认，允许查询。内存中仍有原文件时原样重试；真正重载页面后重新选择文件，必须匹配原始data URL的SHA-256摘要，保留原ID和原文件名。摘要及文件名可持久保存，不保存图片base64或密钥。
- 查询也有超时。只有明确未找到才提供重试；查询不可用不冒充失败。查询成功仍回读当前内容，上传确认后仍须单独保存内容。
- 浏览器存储写入失败时明确提示刷新恢复不保证。原权限、幂等、版本检查、图片服务端校验和保存事务保持。
- EN／ID／ZH固定文字和共用在线指南同步，中文需求维护精确时间与日志。实际页面只验证中文电脑端。

浏览器原生未保存离开保护会阻止自动刷新。早期仅调用reload的步骤不能作为真实刷新通过的证据；本轮隔离入口模拟用户确认离开后重新验证，实际重建页面。3000原离开保护没有修改。

原始证据、前版源码、配置私有副本、测试日志及截图在.local-backups/cms-recovery-fix；模拟库与故障服务停止后保留目录作为证据，不上传Git。

边界：旧版遗留待确认图片若没有原图片摘要，无法证明重选文件与原请求相同，只能先查结果，不补造摘要或更换ID。正式登录系统全矩阵、永久删除、其他语言实屏、移动端和全部主题未重复验收。CMS保存恢复本轮收口，后续优先处理CRM。
