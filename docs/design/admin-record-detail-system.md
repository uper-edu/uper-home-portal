# 管理端记录详情规范

内容页签、记录搜索和筛选控件遵循[管理端搜索、下拉和内容页签规范](admin-list-controls.md)。

适用于 CRM、CMS 和系统管理的记录详情。新增或改造记录详情时使用共享导航和操作区。持续处理多条记录的页面再使用记录侧栏。配置目录、表单弹层和公开站按照各自的现行规范。记录侧栏的样板覆盖客户、商机、营销活动、班次名单、售后订单、用户和角色。

## 操作区

| 位置 | 规则 |
|---|---|
| 标题左侧 | 无常驻记录侧栏时，用 `AdminRecordHeader` 将带实际去向的返回入口与主标题放在同一行，空间不足时允许换行。常驻侧栏可见时，返回主列表位于侧栏标题右侧。上一笔／下一笔和单视图的「查看记录列表」属于记录浏览操作。 |
| 标题右侧 | 使用 `CrmDetailActions`。页面根据当前职责和记录状态决定动作。最多一项主操作，常用的次操作放在左侧。只有一项时直接显示。低频操作适合放进更多操作，状态变化按业务替换动作。没有主要业务动作时可省略主按钮。 |
| 对应信息旁 | 订单核款、凭证查看等只作用于单项的操作放在该项旁。 |
| 弹窗或抽屉 | 提交、取消留在操作层内。关闭时恢复触发控件焦点。从班次名单或商机直达核款时，固定标题区通过 `AdminRecordBack` 明确返回来源，并恢复原筛选、位置和焦点。保存反馈就近显示或沿用共享反馈，不在页头插入新的内容行。 |

后台通知和个人通知设置使用 `AdminOperationLayer` 提供的标题区、滚动正文与底部操作区。需要客户上下文的操作通过 `CrmOperationLayer` 接入同一外壳，由 CRM 工作区提供客户 360 入口和关联客户。

采用共享按钮及语义色。权限不足隐藏入口，可满足的业务前置条件禁用并解释。身份待核实沿用独立琥珀语义。界面展示沿用服务端权限与保存规则。

## 主标题与标题下方信息

- 新增或改造记录详情时，使用 `CrmRecordTitle` 呈现一个主标题，以及可选的状态和识别信息。补充信息紧跟标题并与标题左对齐，作为状态或说明文本呈现，保留下面各业务区块的标题层级。
- 补充区可省略。优先显示会影响当前判断的一个业务状态，再用一行次要文字补充必要的识别信息，如负责人、业务编号或所属记录。状态使用带文字的共享业务样式。识别信息使用 12–13px 的共享次要文字色，短字段之间用 `·` 分隔，空间不足时允许自然换行。
- 当前记录的关键状态与识别信息优先放在标题下，同一字段在本详情的摘要中只出现一次。摘要保留关联入口、下一步等独立信息。正文中的历史状态和单条业务记录保留其当时的上下文。缺失的可选字段省略，业务上有意义的「未分配」等状态按原口径显示。编号与姓名保留原值，固定标签提供中、英、印尼三语。
- 客户在姓名下显示当前阶段、负责人和客户编号。商机列表、侧栏和详情统一使用「学员姓名 · 课程级别」，无学员姓名时用客户姓名。商机标题下显示当前阶段和负责人，存在待核实身份时优先显示该状态。摘要保留关联客户和可执行的下一步。学员与关联客户姓名相同时，以客户编号提供跳转入口。当前有权查看的列表范围内出现同名同级商机时，列表、侧栏和详情标题下使用同一商机编号。编号优先用现有商机 ID 的末八位，末八位也相同时显示完整 ID。切换详情页签时保持识别信息的位置稳定。

## 右侧内容区

- 采用记录详情面板的共享表面、边框、标题留白与正文边距。摘要需要承载关联入口或下一步时，使用标题下的浅底区。
- 正文按实际业务信息分区，使用有语义的二级标题和分隔线。操作跟随对应记录。内容有多组且确实需要切换时再用页签。桌面两栏独立滚动时，右侧标题与摘要保持可见，重点记录只在正文内定位。

## 记录侧栏

- 使用 `CrmRecordSidebar`、`CrmRecordRow` 和 `CrmRecordFilters`。栏宽基准 320px，标题 16px，记录名 14px，辅助信息 12–13px。行块统一分隔、选中标记和可见键盘焦点，浅深色使用管理端语义变量。业务方提供记录名、负责人、业务状态及必要的本域信息。
- 标题显示匹配数，常驻搜索和带已选数量的筛选入口。次要条件在同一侧栏的限高浮层显示，展开不挤动记录或详情。复用共享下拉，条件即时生效，关闭保留条件。先由内层下拉处理 Esc，再关闭筛选并恢复焦点。
- 从大列表进入时沿用筛选与排序。两处使用同一份条件和结果规则，返回仍带上侧栏修改。沿用该列表已有的分页和位置恢复机制。
- 筛选排除当前记录时，授权仍有效的详情和草稿保持打开，并显示提示。切换记录或离开时沿用草稿确认流程。收到范围撤销及时清除不可访问数据。加载、失败、暂无符合条件和有结果分别呈现。
- 可用空间足够时两栏独立滚动，选中记录仅在必要时在侧栏内部定位。窄屏和低高度沿用记录工作区单视图及导航方式。样板验收包含搜索、筛选、切换、返回恢复、草稿、焦点和浅深色。
- 详情统一使用 `useAdminRecordSidebarLayout` 提供侧栏、页头返回和单视图切换。桌面双栏常驻，使用 `AdminRecordSidebar` 在标题右侧呈现唯一的返回主列表入口。营销活动的刷新和创建集中在活动中心主页页头。页面继续提供实际返回路径与对应的筛选、排序、分页、阅读位置、焦点及草稿处理。
- 单视图显示详情时，返回主列表在详情页头。点击「查看记录列表」后焦点移入侧栏，返回主列表移到侧栏标题右侧。「返回详情」保留已打开记录并回焦到「查看记录列表」。
- 售后订单详情在宽度达到 1120px 时常驻「售后订单」侧栏。可用高度不足时改为页面自然滚动。宽度不足时，在详情和订单侧栏间切换。侧栏查询覆盖当前账号可访问的售后订单，与主列表共用搜索、班次、报名状态和售后进度。条件变化时回到第一页，返回主列表带回筛选；仅在侧栏翻页时，返回恢复原主列表页码与位置。当前订单未出现在侧栏当前结果时，单独提示，右侧保留已授权的订单。

## 折叠内容与原文返回

- 页面内展开使用 `AdminDisclosure`，保留原生展开语义。鼠标、Enter 和空格均可展开或收起，焦点留在标题。表格回执、审计记录和账本处理详情用紧凑样式，独立说明区用面板样式。客户全景的时间轴卡片共用展开箭头，保留卡片布局和原有展开规则。
- 「发送记录」通过记录链接直达时只展开目标行的技术回执，再定位并聚焦该行。在列表内手动查看不改变状态筛选或页码。从客户全景打开对话后，通过标题操作区的「返回客户全景」恢复原筛选和搜索，再将焦点交回打开对话的原按钮。

## 系统管理记录

「用户」和「角色」从主列表进入只读详情。列表和详情侧栏共用搜索、筛选和记录组件，查看权限与编辑权限分别判断。系统管理通过「用户与权限」进入用户、角色和变更审计三个共享页签，默认打开用户。审计页签遵循原有审计权限。用户详情区分已分配角色和当前生效权限，并按业务分组使用共享表格呈现生效权限，每项一行，列为权限、生效范围、来源角色；各来源角色可单独打开详情。旧的独立权限预览链接转入用户详情。角色详情展示授予权限和适用范围。新增、编辑、角色保存前的影响预览和敏感操作沿用原有编辑抽屉及确认流程。

## 页面与配置主题页头

销售管理和系统管理的一级页面使用 `AdminPageHeader`。主标题 20px／28px、字重 700，左侧与工作区正文对齐。标题首行与右侧操作共用 40px 对齐高度。主标题下必有一段 13px／20px 的用途说明，通常一句，写清当前页面可完成的工作。同一页面的页签用途不同且共享标题时，说明跟随当前页签。桌面工作区共用 1560px 最大宽度及 24px 内边距，空间不足时右侧操作可换行。

目录型设置页面的右侧使用 `AdminTopicHeader`，主题标题 18px／26px，标题下使用同规格的简短用途说明，当前主题的刷新、保存及其他操作放在标题右侧。记录详情继续使用详情标题和操作区。

本地 3000 构建 `46505c1952d4-d983179be3381a84` 用中文桌面和模拟响应检查了销售管理与系统管理的 24 个入口，其中 10 个入口同时检查右侧主题标题。在 1440px 宽度核对主标题坐标、字体与操作对齐，并在 1720px 深色模式复验营销活动中心和集成配置的页头。

标题说明在本地 3000 构建 `46505c1952d4-a24cbd0c271f9e98` 用中文桌面和模拟响应复验 35 个入口，其中 20 个同时核对右侧配置主题。已核对说明的位置和字号，以及用户、角色、变更审计、报名、售后、收款和邮件各相关页签的对应文案。
