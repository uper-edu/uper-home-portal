# CRM 购买信号来源与精确定位验收

日期：2026-10-17。范围：独立本地 4426 / MySQL 模拟数据。未切换 3000、未推送 GitHub、未部署服务器。

## 已交付

- Profile 客户分组内区分实际购买意向信号、问卷关注内容和缺少可追溯证据的历史资料。
- 展示记录来源、可靠时间（运营时区，精确至秒）、员工及原始消息或人工备注。问卷选项采用三语可读名称，不伪装成客户自由输入原文；缺失时间不推算。
- Chat 的明确预约和报名请求关联原始客户消息、请求证据及任务，并区分新建任务和补充已有任务。转人工请求本身不等同购买意向。
- 工作列表优先显示最近实际信号；点击后打开 Profile，定位对应证据，短暂青绿色高亮并转移键盘焦点。问卷关注内容仍明确标注类别。
- 原文入口定位 Conversations 中的具体消息；任务入口定位 Follow-up 中对应任务。保留现有草稿离开保护。
- 购买信号筛选使用有来源的实际信号，不把问卷选项或无法追溯的历史聚合值当作实际咨询。
- 同步英文、印尼文、中文及在线指南。

## 实现与数据边界

增加只读证据投影，供已授权客户列表与详情共用；不新增数据库迁移，不回写历史事实。聊天消息关联同时限制客户、会话及请求标识。

Tier 算法及其已有输入字段保持不变。因此客户原有 Hot 等分组可能继续存在，本轮不能解释为已修复分类算法。不同消息的相同内容分别保留；重试同一请求不新增重复证据。普通 AI 对话不新增未经验证的意图推断。
