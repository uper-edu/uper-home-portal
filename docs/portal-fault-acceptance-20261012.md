## 确认的待修复问题

2. 两入口应准确表达保存状态。数据库或网络错误不得仅给出通用网络提示；用户文字应保留为未保存并提供复用消息 ID 的安全重试。流式处理应依据 saved 和最终 done 区分已保存、生成中、失败／中断，不能把流结束等同于完成。
3. 刷新后消息顺序不稳定：用户和助手在同一事务内插入，created_at 相同；当前 ORDER BY created_at,id 用随机 UUID 打破平局，可能把助手排在用户前面。应引入稳定顺序，并覆盖恢复显示与模型历史读取。
4. 中断记录目前只能重新提问；对原请求的安全续生成／重试路径仍需设计。须保留幂等约束与失败尝试，避免复制用户消息。
