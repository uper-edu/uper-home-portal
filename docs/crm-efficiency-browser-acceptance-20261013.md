# CRM 销售效率：窄屏、浏览器故障及无障碍补充验收

日期：2026-10-13。本轮只更新独立测试环境 `http://127.0.0.1:4402/crm`，数据库为 `crm_efficiency_workflow_test_20261013`，使用模拟客户及 Fadhil 销售角色。4403 为仅监听本机的临时故障代理，验收结束后停止。没有切换 3000、推送 GitHub 或部署公网。

## 发现并修复的问题

1. 手机导航的长模块名被截断：小屏改为两列换行，主要入口保留可点击尺寸；快速跟进表单缩小外边距。
2. 客户筛选折叠控件在未显示自定义标题时出现浏览器默认 `Details`：始终提供对应语言的标题，按显示状态隐藏。
3. 深色选中导航、联系预览输入框和错误文字的颜色不一致：统一主题背景及前景；浅色未选语言文字由 `#64748b` 加深为 `#475569`。列表动态原依赖全局 dark 类，实际 CRM 主题切换时未生效，改用工作区主题；选中客户行的普通截止时间和辅助文字也统一加深。
4. 联系预览打开后焦点不明确：聚焦标题，Escape 关闭后回到触发入口；入口已移除时回到客户标题。表单错误聚焦带 alert 语义的提示，增加三语“跳到工作区”链接和主要内容区域。
5. 数据轮询发现会话失效或客户归属变化时，面板关闭导致草稿丢失：草稿按员工保留在本页内存。失去权限后关闭旧客户资料，只显示员工本人尚未保存的输入；同一员工重新登录并获得访问权限后可恢复。不同员工不能访问该草稿，主动退出清理；刷新或关闭整个页面仍会清除未保存内存，在线手册明确说明这一边界。
6. 登录状态检查把暂时断网当作退出：只有明确 401／403 才退回登录；网络或服务故障保留界面、草稿及重试入口。
7. 保存响应长时间不返回：20 秒超时后显示“结果尚未确认”，保留输入及请求 ID。冻结原销售阶段、联系安排版本和原联系状态，避免轮询已经更新资料后，相同重试意外变成不同请求。
8. 浏览器原生必填提示跟随浏览器语言：改由服务端校验并使用 CRM 三语错误映射，缺少记录时明确提示填写记录，而非含糊的失败信息。

## 窄屏与键盘验收

| 检查 | 结果与证据 |
|---|---|
| 390／768／1280px × 英／印尼／中 × 四页签 | 36 组通过；实际 `innerWidth` 与目标一致，整页 `scrollWidth` 不超过 `clientWidth`，客户上下文一致 |
| 390／768px × 三语跟进表单 | 6 组通过，表单、任务选择及保存入口未导致整页横向溢出 |
| 控件名称 | 上述页签检查中，可见表单输入及按钮没有发现空的可访问名称 |
| 下拉键盘 | Enter 打开，方向键移动，Enter 选择后焦点返回触发按钮；未保存选择未写入业务数据 |
| 页签与跳转 | 方向键切换页签并聚焦对应页签，Home 返回首项；跳转链接聚焦 `crm-main` |
| 预览与错误 | 打开预览聚焦标题；Escape 关闭返回 WhatsApp 入口；服务失败及超时错误提示获得焦点 |
| 三语、浅深色 | 三语布局及主要文字已复核；客户原文、姓名和人工备注保持原文 |

视口工具作用于当前活动页，非活动页可能仍为 1280px；验收记录以实际 DOM 尺寸为准。浏览器 110% 缩放下，429／845／1408 的外层尺寸分别得到实际 390／768／1280 CSS 像素。此前未生效的请求参数不计入通过结果。

对比度检查使用计算样式及祖先背景的透明合成，支持 RGB、OKLCH、OKLab。普通小字采用 4.5:1；装饰分隔符、隐藏图标和禁用入口不当作有效文字失败。标准依据：[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这属于指定界面的对比度、键盘与语义检查，不是完整 WCAG 认证，也不是 VoiceOver／NVDA 实际用户验证。

最终列表、四页签、表单错误及深色话术预览共采集 476 个浅色、497 个深色文字样本（包含跨页签重复控件），计算结果均达到上述文字阈值。没有把禁用控件、图标或分隔点计入这一数字。

## 浏览器故障组合

| 故障 | 实际结果 |
|---|---|
| 任务查询 503 | 显示任务暂不可用及重试入口，不把失败显示为“暂无待办”；恢复后读取真实任务 |
| 保存前 503，使用保存并下一位 | 草稿与当前客户保持，不跳转、不新增记录 |
| 服务端已提交，响应改为 503 | 相同内容重试成功；数据库只保存一条记录 |
| 打开表单后，管理者将客户转给其他销售 | 关闭失权客户资料；保留本人草稿文字；旧员工未保存成功。恢复归属后可重新打开并恢复草稿 |
| 保存收到 401 | 显示登录要求，不假报成功、不跳转；输入保留 |
| 服务停机超过 60 秒，登录状态定时检查遇到断网 | 界面不误退出；草稿保留。重启独立服务后保存一次成功 |
| 真实测试会话过期，再用同一员工重新登录 | 回到登录，旧资料关闭；同页重新登录恢复原草稿，保存一次成功 |
| 恢复联系事务已提交，但响应延迟 25 秒 | 浏览器 20 秒提示结果未知；轮询更新了联系状态后仍能以相同请求重试成功；仅一条恢复记录，业务任务期限不变 |

以上故障只针对 4402 和临时 4403 代理，不对 3000 或真实 Lark 服务注入故障。再次查询数据库验证了丢响应、断网、重新登录及延迟响应的记录均没有重复；失权草稿没有入库。

## 模拟销售完整跟进流程

承接已通过的 Campaign → 带活动 ID 的 Chat → 问卷 → 快速测评 → 真实 OpenAI 咨询 → Fadhil 认领 → 未回复 → 等待／复查数据，本轮实际操作：

1. 复查客户诉求、原人工摘要和当前任务，说明原因恢复主动联系；保留原业务任务。
2. 从明确任务进入，确认本次联系为“已接通／已回复”，记录人工原文；只选择该咨询任务完成。
3. 明确将销售阶段由 New 改为 Contacted；记录核实真实排课及费用的动作，不编造席位或优惠。
4. 安排下一工作日 09:00（Asia/Jakarta）的后续任务，保存后核对咨询任务 completed、旧复查安排 cancelled、新跟进任务 open。
5. 已完成咨询任务没有待发通知；原测评仍为 0/30，未修改评分。新普通任务尚未到期时，该客户离开“需处理”，仍在“全部”中。

多任务客户原预约及报名截止时间仍为 2030-01-01T10:00:00Z；本轮没有完成这两项。模拟客户原测评分数 8 保持不变。只完成选定任务，没有按客户批量完成全部任务。
