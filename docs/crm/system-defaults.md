# 系统初始化预置

统一MySQL建库入口为cloud/mysql/migrate.mjs：完成全部表结构后，在schema锁内以单一事务初始化系统记录，不依赖首次页面访问。Local、测试和生产使用相同代码和预置数据；环境文件仍分别管理凭证和运行配置。仅手工创建空数据库或单独执行schema.sql不等于完成初始化，应执行完整迁移入口。

默认记录：

- `organic` 是 CRM 为没有来源信息的新登记使用的自然来源。从无推广参数的 `/link` 进入咨询，只会记录 `linkhub` 页面入口。
- `instagram-bio` 是预置的 Instagram Bio 活动，包含中、英、印尼语三条推广链接。通过这些链接进入 `/link`，再转到 `/chat` 时，页面会保留推广标识 `p` 和已有的 UTM 参数。直接访问无推广参数的 `/link` 不会自动归到此活动。
- finance角色：仅crm.read和crm.payments.verify，不扩大CRM经理模板。
- 8门HSK标准课程和报价：直接读取src/data/crmCoursePrices.json，来源为已确认的FAQ q53；发布状态开启，默认优惠权限为0，金额为IDR。报名仍保存当时报价快照。

账号首次初始化仍经过现有安全密码机制，不把密码写入SQL或预置JSON；新建系统预置账号Suki和Robert的角色包含finance，其他账号不因此获得核验能力。已有账号的密码、角色、权限及会话不因重复初始化被覆盖；管理员之后撤销财务权限不会在重启时被加回。因此已有环境中尚无财务角色的Suki需要另行受控授权，修改默认模板本身不会越过现有账号保护。

重复执行只补缺失数据，不清零统计、不覆盖调价、上下架、自定义角色或历史。标准课程使用稳定ID；旧版人工预置的同名课程保留原ID及原报价。多个同名旧课程无法唯一对应时中止，不猜测合并。预留活动ID／代码或已核实归因别名有冲突时中止并回滚，不改写来源历史。离线迁移副本或恢复安全屏障中的数据库不运行此预置步骤。

测试夹具可以显式initializeSystemDefaults=false构造空业务场景；正式建库默认开启。预置清单与应用活动定义、财务模板有一致性测试，课程直接复用正式价目文件。
