## 1. 业务目标与概念

任务（Task）是需要员工执行、可以明确判断完成与否的工作，不是客户标签、聊天消息或通知。每项工作应能回答：做什么、依据是什么、谁负责、最晚何时回应／何时执行、如何结束。

| 概念 | 业务含义 | 边界 |
|---|---|---|
| 任务类型（Task type） | 回应咨询、确认预约、处理报名、普通跟进、内部复查等类别 | 同类不等于同一件事 |
| 具体事项（Business matter） | 如“确认客户本周六A班试听” | 不能仅凭文字相似、类型或同一客户推定相同 |
| 客户请求（Customer request） | 客户的一项明确诉求及原文、收到时间 | 可产生任务，也可等待关联判断；不是已解决的标记 |
| 来源依据（Source evidence） | 消息、表单、人工记录及来源标识 | 保留原文；不由AI编造客户事实 |
| 信息动态（Activity） | 新消息、资料和测评变化等事实 | 不必每条建任务；已读不等于处理完成 |
| 通知（Notification） | 告知员工某项工作或异常 | 发送成功不完成任务；通知作业不是销售任务 |
| 任务负责人（Task owner） | 需要处理这项工作的员工 | 与触发者、创建者分开；不因协助自动改变客户Owner |

任务不保证成交。任务的价值是及时回应和兑现安排；销售阶段、购买信号、测评及试听结果仍是独立记录。

## 2. 当前创建路径清单

“当前”表示源码路径存在，不表示本轮重新完成端到端验收。入口按业务名称描述；实际可见性受现有权限和客户状态约束。

| 编号／场景 | 触发条件和当前创建规则 | 触发者／创建者 | 当前入口 | 负责人及时间 | 当前去重／关联 |
|---|---|---|---|---|---|
| C01 首次登记Lead | 访客首次成功登记联系信息，创建初次联系任务consultation | 客户／系统 | 主页助手或独立Chat的联系信息登记 | 默认客户Owner，未分配则任务Owner为空；按分组及SLA配置计算响应期限 | 已关联Lead再次登记不重复走首次建任务分支 |
| C02 官网咨询 | 有效Contact表单提交；无同类开放任务则建consultation，否则沿用 | 客户／系统 | 官网Contact表单 | 默认客户Owner；按consultation的SLA | 同一提交重试去重；同Lead已有开放consultation时复用，不为每次表单建任务 |
| C03 顾问联系请求 | 有Lead，明确请求顾问联系，且没有同类开放任务 | 客户／系统 | 主页助手、独立Chat的顾问按钮或识别到的明确文字 | 默认客户Owner；按紧急请求SLA，自原消息时间计 | 同一来源请求重试返回原结果；已有同类任务则保存待确认请求，不直接新建或覆盖 |
| C04 预约请求 | 同上，诉求为booking | 客户／系统 | Chat的预约入口／明确表达 | 同C03 | 预约请求不等于确认了试听场次 |
| C05 报名请求 | 同上，诉求为enrollment | 客户／系统 | Chat的报名入口／明确表达 | 同C03 | 报名意向不等于报名或付款完成 |
| C06 匿名请求补关联 | 尚无Lead时请求先保存；登记后将未关联请求接入C03～C05 | 客户后续登记／系统 | 登记后的后台关联流程，无需员工再复制消息 | 按原始请求时间计算，不从员工发现时间重新计时 | 保留会话、消息、请求类型；同类开放任务继续走关联判断 |
| C07 普通人工新增 | 明确保存独立事项，任务内容和未来时间必填，说明选填 | 有客户写入权限的员工／该员工 | 客户→Follow-up→新增任务 | 默认客户Owner；员工按运营时区选择未来时间及含义 | 保存编号幂等；已有任务仍保留；不靠动作文字自动去重 |
| C08 跟进后安排下一步 | 保存处理结果时选择安排下一步；选择新建才创建，补充或改期不创建 | 有权限员工／该员工 | 记录联系／处理任务→后续安排 | 默认客户Owner；员工选择时间 | 与记录及选定任务处理同事务；独立新建已与C07统一说明选填；补充、改期、替代和复查仍要求对应依据 |
| C09 待确认请求另建 | 同类新请求已保存，员工明确判断是独立事项 | 有权限员工／该员工 | Follow-up→待确认关联的新请求→另建任务 | 默认客户Owner；沿用该请求原响应期限，不能为了建任务重置SLA | 校验请求版本和状态；可改选补充到现有任务；另建只需任务内容，说明选填；原文及期限自动带入 |
| C10 稍后复查 | 明确复查内容、原因、未来时间；可明确约定此前不主动联系 | 有权限员工／该员工 | 调整联系安排／跟进表单→安排稍后复查 | 默认客户Owner；明确复查时间 | 改复查安排只处理关联旧复查任务并建立新记录，不改其他任务期限 |
| C11 替代原工作 | 明确确认同一事项原工作不再需要，填写新工作、时间及原因 | 有权限员工／该员工 | 原任务菜单→替代；或后续安排的替代选项 | 按现有创建逻辑默认客户Owner；原负责人差异需明确展示 | 原任务取消、新任务关联原任务；不是完成，不擦掉原期限和逾期 |

当前Chat的手输识别是保守的三语表达匹配。普通问答、否定、条件、引用或多种冲突意图不等于明确请求，可能继续AI咨询；不能宣传为理解所有自然语言的自主销售决策。

## 3. 目前不会直接创建销售任务的变化

| 变化 | 当前结果 | 是否需要改为自动建任务的建议 |
|---|---|---|
| 普通新消息、重新进入会话 | 消息、动态或事件及按策略提醒；不保证建任务 | 不全量自动建。必要时让员工明确安排；客户真实诉求不得因已读消失 |
| 完成测评／更新成绩 | 保存测评事实及相关事件 | 仅对确需人工解释的情形设计待确认事项；不得修改评分或自动承诺分班 |
| 识别疑似同一人 | 身份候选关系、核实入口及相应限制 | 当前不是followup_tasks任务。后续先明确Manager处理责任及期限，不能直接伪称已有统一任务化 |
| 未知Campaign产生Lead | 待核实来源记录 | 属于来源管理工作，不为每位Lead复制一张销售联系任务 |
| 认领／分配／Owner变更 | 归属及相关路由处理 | 不因分配本身复制任务；任务交接完整性须单独验证，不能仅凭通知路由正确推定完成 |
| 任务到期、改期后的约定时间到达 | 原任务逾期状态或到期事件 | 提醒原工作，不再造第二项同义任务 |
| AI回复失败、通知失败 | 异常及执行记录 | 属于内部异常处理；不是自动建“联系客户”的充分依据 |
| 分组或销售阶段变化 | 按既有规则更新对应记录 | 不机械建任务，不据此自动完成或重算旧期限 |
| 有效未回复联系达到规则条件 | 联系序列及符合条件的分组处理 | 当前没有完整自动重试任务链。可提供下一次建议，由员工确认，不一次预建三张拨打任务 |
| 查看客户、已读、复制话术、打开电话／WhatsApp | 查看或联系意图留痕 | 均不自动完成任务或算作真实人工联系 |

## 4. 统一业务规则：设计目标与实施状态

| 规则 | 目标规则及业务结果 | 状态 |
|---|---|---|
| R01 建任务的门槛 | 有明确待执行工作，且能够说明内容、责任和时间。普通信息先保存，不每条消息建任务 | 部分实现；全入口口径待统一 |
| R02 原请求重试 | 同客户、会话、消息及请求类型的同一来源返回原结果；旧任务已结束也不因重试重开 | 已实现相关去重；按既有验收边界 |
| R03 同事项补充 | 原任务未结束，新信息不改变原工作时补充原任务；保留原文、原期限及状态 | 已实现员工明确补充；不自动推断任意消息关联 |
| R04 同类型不代表同事项 | 无法判断时保存待确认关联请求，展示原文及可关联任务；不能吞掉新请求 | 已实现同类请求待确认；事项信息展示仍可完善 |
| R05 独立事项并存 | 不同工作新建，并存但有优先级；新任务不偷偷完成、取消或改期旧任务 | 已实现 |
| R06 改期 | 仅改执行安排，展示原因和变更历史，保留原截止及已发生逾期 | 已实现相关路径；复查改约走联系安排 |
| R07 替代／取消 | 原工作确实不再需要才操作，必须原因；替代建立新旧关联，不伪装完成 | 已实现 |
| R08 普通新增统一 | 所有普通新建入口都用内容＋未来时间必填、说明选填；来源和已有记录自动带入，不要求重复抄写用途 | C07、C08、C09已统一，本地定向通过；详细验证范围见入口统一验收 |
| R09 请求转任务 | C09保留客户原文和原响应期限；即使已逾期也不因当前新建而重算。不是要求员工补造“未来请求时间” | 已实现原请求期限沿用；表单精简待统一 |
| R10 完成按事项 | 只完成明确选中的任务；接通／发消息不等于全部诉求解决。完成前提供该类工作应核对的结果 | 显式选中完成及六类辅助指引已实现；不新增自动判断完成的引擎 |
| R11 一次操作多项成果 | 一次沟通可以解决多项任务，但必须逐项确认真实结果，不能系统默认全选或批量关闭 | 已有单任务绑定、完成指引及重叠提示；当前一次只处理一项，其他事项仍分别确认，不支持一键批量结束 |
| R12 留下后续去向 | 保留有效安排、明确新安排或按联系规则处理；只记录事实允许保存，不冒充闭环完成 | 已实现相关选择；各入口一致性待完善 |
| R13 责任人可见 | 分开触发者、创建者、任务负责人及客户Owner；代处理自动留痕，不改客户归属 | 部分实现；未分配任务队列及交接完整性待专项核对 |
| R14 先做内部核实 | 身份、未分配、停止及明确暂停等条件限制执行动作，不自动完成或抹去任务；必要时先展示内部工作 | 已有P0约束；不要把身份候选说成已建普通任务 |
| R15 请求有时限 | 等待人工判断关联时仍计算新请求响应期限，不能因没有新任务而漏掉超时 | 已实现请求期限及到期事件；关联处理效率待使用验证 |
| R16 优先级有依据 | 原逾期→今天到期→明确请求→其他有效安排；执行前先处理身份等必要前置条件；同组稳定排序 | 已有单客分桶；内部核实与普通任务统一工作表现待完善 |
| R17 时间含义分离 | 响应截止、约定执行、内部复查明确区分；原期限和新安排都可查 | 部分实现；各创建入口与类别统一待完善 |
| R18 联系限制独立 | 普通未来任务或普通review时间不自动禁止联系；明确约定此前不主动联系才限制；停止仍须明确恢复 | 已有P0实现，不新增“暂停状态” |
| R19 通知服务任务 | 新建／改期／到期按现有策略，Owner→Manager兜底；发送或已读不完成工作，历史不重放 | 已有链路；不因文档设计调整策略或启用补发 |
| R20 Offer有依据 | 允许任务关联经核实Offer及有效期，不自动编造价格、席位或承诺；无可靠来源时先核实 | 关联Offer及决策流程待设计，本轮无推荐算法 |

R08不将“补充到旧任务”“取消／替代／改期原因”“身份决定依据”改成选填，也不把新请求已有的过期期限强行改成未来。它只减少普通新增的重复录入。

## 5. 谁创建、谁处理与权限

1. 系统只按已定义触发创建，不以AI生成的营销判断任意建任务。客户是触发者，系统是创建者；负责人默认继承客户Owner。
2. 有该客户写入权限的Sales和Manager可使用相应人工入口，服务端保存前重新检查。系统管理员身份本身不增加CRM业务权限。
3. 未分配的系统任务不随机指定销售。当前Owner为空不等于无事可做；通知按现有Manager兜底规则。建议在已有单客工作区清晰展示“待分配”，跨客户任务中心仍为backlog。
4. 销售先认领再主动联系；具体认领／分配资格继续受配置及现有权限控制。身份待核实先核实，不自动认领；停止联系和明确日期约定不被新增任务绕过。
5. Manager有权限时按既有规则协助，系统记录实际操作人及当时Owner，不新增普通协助审批或强制解释。特殊身份核实／约定期内回复沿用P0所需依据。
6. 能创建或查看任务不等于能主动外联，也不保证能完成其中任意工作。保存与执行检查最新权限、身份及归属；内部笔记和复查不能伪记人工联系。
7. 任务Owner与客户Owner不一致时显式显示差异；是否跟随客户转移，须沿用并核实当前交接实现，不能本轮仅凭设计自动改存量归属。

## 6. 任务最小信息与时间口径

| 信息 | 员工是否填写 | 设计要求及当前边界 |
|---|---|---|
| 任务内容（Task content） | 人工普通新增必填 | 具体可执行，如“发送周六课表，并确认客户可上课时间”；系统请求用可解释的类别与原文支持，不能伪造承诺 |
| 任务时间（Task time） | 人工普通新增必填 | 运营时区明确显示；未来时间校验；请求转任务保留原响应截止是例外，不重置历史 |
| 时间含义（Timing kind） | 有合适默认，可修改 | 响应截止／约定执行／内部复查；不是要求填三次时间 |
| 补充说明（Additional notes） | 普通新增选填 | 默认收起；不自动塞入重复内容或“无”等占位；其他操作依据按各自规则 |
| 来源及原文（Source evidence） | 自动带入，人工可关联已有记录 | 保留来源时间和ID，避免重复抄写；选择来源不能越权读取 |
| 负责人／创建者／触发者 | 自动记录为主 | 不新增强制人员下拉；默认Owner及例外须清晰展示 |
| 原截止／当前安排 | 系统保留 | 不因改期、分组或Owner变化擦掉逾期；复查改约保留旧记录 |
| 事项关系与历史 | 员工必要时判断，系统记录 | 独立、补充、替代及具体目标；不是按文字相似度自动决定 |
| 完成指引（Completion guidance） | 系统展示，员工确认结果 | 已展示六类文字指引；不是结构化完成结果验证引擎，不新增必填字段 |

当前自动SLA按类型／分组选配置时长：顾问、预约、报名请求走较紧急配置；初次咨询按分组配置。实现是先顺延到工作时间，加自然时长，再将落点顺延到工作时间；不是累计营业小时。本文不写死本机具体小时数，也不改SLA算法。后续如需改成营业时长累计，必须单独评审。

## 7. 事项变化处理表

| 收到的变化 | 判断和动作 | 必须保持 |
|---|---|---|
| 同一报名按钮网络重试 | 返回原回执 | 任务数和期限不变 |
| 客户再次要求同一次试听，并补充同行人数 | 员工确认关联后补充原任务 | 新原文可查，不覆盖原期限 |
| 同客户要求另一天试听另一课程 | 确认独立事项后另建 | 与旧预约并存，不按booking类型强行合并 |
| 初次联系任务尚在，客户提出报名 | 可同时存在；一次沟通确实解决两项时逐项确认 | 不是收到报名意向就自动完成初次联系 |
| 客户仅问了课程价格 | 普通问答不保证自动建任务；如销售承诺稍后报价则明确安排 | 不把报价问题解释成已报名 |
| 未接通 | 保存真实尝试，选择保留已有安排或明确下一次行动 | 不默认完成诉求任务；不自动预建多张拨打任务 |
| 客户更改已确认的回电时间 | 明确改期并说明原因 | 原期限、逾期、原文均保留 |
| 原场次取消，改做另一场次 | 明确取消／替代并说明原因 | 旧任务不是完成，新旧关系可查 |
| 客户要求某日前不要联系 | 明确建立带该约定的复查安排 | 原业务任务和期限保留，复查到期不等于任务完成 |
| 任务期间发现疑似身份重复 | 先核实身份，限制外联；已有工作仍可追溯 | 不自动转Owner、合并历史或完成任务 |
| 测评已完成但尚无人工安排 | 保存结果；是否需要人工解释另行明确判断 | 不自动分班、不改HSK评分、不虚构后续任务 |

## 8. 按工作类别提供完成指引（已实现，验证范围见报告）

以下已作为任务卡片可展开说明及处理表单的直接提示；[本轮验收状态](./TASK-GUIDANCE-ACCEPTANCE.md)。这是帮助员工判断的指引，不是新增一串必填表单，也不把客户业务结果强制绑定为“必须成功才能结束”。无法完成时应按权限明确取消／替代并说明原因。

| 工作 | 完成前需要确认 | 不能冒充完成的情况 |
|---|---|---|
| 初次了解需求 | 记录实际联系结果及已了解内容，明确后续 | 只打开WhatsApp，或把一次未回复直接当作已满足客户诉求 |
| 回应顾问请求 | 请求已被真实处理，结果和后续可查 | AI回复、提醒已读或未经确认的已发送 |
| 确认试听安排 | 已核实客户需求和可行场次，记录确认结果；取消则明确记录 | 仅收到预约意向就标已确认或已到场 |
| 处理报名请求 | 记录客户需要的报名支持及处理结果；付款／报名事实独立记录 | 联系成功就标成交或付款 |
| 执行人工承诺 | 对应内容已实际交付，或明确记录变更／取消 | 泛写“已跟进”却没有兑现承诺 |
| 内部复查 | 已检查变化并决定继续安排、恢复或停止等后续 | 时间到了自动完成，或自动发消息 |

## 10. 实施验收规则（按阶段核对，不表示全部通过）

P0-A只覆盖本次受影响路径：普通新建及请求另建可省略说明、原请求期限保留、重试、变更原因和权限保护；详见入口统一验收。以下全清单并未在本轮重新逐项执行，不将过往测试当作本轮全覆盖。

| 编号 | 场景及预期结果 |
|---|---|
| A01 | 首次登记仅建一项初次任务；登记重试不重复。官网咨询沿用已有开放consultation时不复制 |
| A02 | 匿名明确请求登记后关联到正确Lead及原消息，按原请求时间计算，不串访客 |
| A03 | 同一请求十次重试返回原结果，不重复任务、原文或审计；历史关闭任务不重开 |
| A04 | 新顾问／预约／报名请求无同类任务时建任务，有同类时保留待确认原文和期限 |
| A05 | C07、C08普通新增只填内容和未来时间可保存；不填说明不伪造用途，填写则保留原文；历史用途不改 |
| A06 | C09另建使用原请求期限，包括已过期请求；不要求员工输入假的未来SLA，不重置起算时间 |
| A07 | 同类不同事项可明确另建；同事项补充不改变原任务、期限或Owner |
| A08 | 取消、替代、改期无原因拒绝；替代留新旧关联，原工作取消而非完成；复查不得经普通菜单绕过 |
| A09 | 不填内容、无效时间或普通新增过去时间拒绝，草稿保留；显示运营时区；跨时区转换正确 |
| A10 | 同时有初次联系、试听、报名三项时，只结束选定且实际已处理项，其他工作及原期限保留 |
| A11 | 仅联系未回复、读消息、打开工具不自动完成；记录事实与后续已安排分别展示 |
| A12 | 身份待核实、未分配、停止及约定期限内外联仍按P0拦截；Manager普通协助不新增审批；有效特殊回复按既有规则 |
| A13 | 幂等／并发／事务失败不重复、越权或丢草稿；保存前重新核对任务、请求及权限版本 |
| A14 | 完成选定任务只取消对应待发通知；已接口接受／未知不伪装撤回；不重放历史 |
| A15 | 未分配任务显示待分配及Manager责任；有权认领后责任可辨认，不将通知收件人冒充任务Owner |
| A16 | 请求待关联期间仍有原响应期限和超时提示；补充请求不静默覆盖旧任务期限 |
| A17 | 分组变化、Owner转移或改期不擦掉原任务期限；任务交接按批准规则专项核对，非本轮改归属 |
| A18 | 三语的动作、来源、时间含义及状态一致；客户原文保留；PC关键入口可键盘操作；范围仅覆盖受影响功能 |

验收使用本地3000模拟客户定向验证；并发、时间推进、故障及可能真实外发的路径采用独立MySQL／模拟通知。保留现有账号、权限、Owner、任务期限和配置，区分已有验收证据与本轮新验收。真实销售使用验证另行安排。
