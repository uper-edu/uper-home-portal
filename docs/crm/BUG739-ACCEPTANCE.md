# #739 自然表达与试听请求：需求、方案与验收

## 需求判断

“请帮我预约本周六下午三点的线上试听”和“我想预约明天下午的试听”是客户当前明确提出的试听请求，不是客户与销售双方确认的约定。请求应进入“诉求与意向”，保留原文及提出时间。期望时间不能变成约定时间，也不能误作长期可上课时段。

## 最终技术方案

- 自由输入统一保存原消息并进入正常AI咨询，取消调用AI前的文字正则分流；明确按钮／用户主动选择的顾问模式与旧在途请求幂等路径保留。
- 复用服务端异步提取。v5合同新增trial_request、enrollment_request，与trial_interest、enrollment_interest分开；保留原文引用、主体和时间语义。
- 仅新版本、未被修正关联的新客户消息可根据当前明确请求创建结构化请求。相同消息＋请求类型幂等。历史来源不重跑、不补发通知。
- 只有当前客户明确请求可形成请求记录；否定、撤回、条件、历史、引用等不形成新的肯定请求。模型不猜测撤回哪条历史记录。
- 同一原消息的明确请求优先于较弱的同义意向；其他来源历史保留。原文依据中的AI约定陈述标明未经销售确认，不进入有效客户约定。
- 程序继续校验权限、来源、格式、幂等和状态。未引入第二套模型服务、通用任务、预约排期、评分变化或自动销售阶段迁移。

## 结果规范举例

| 客户原话 | 提取语义 | CRM结果 |
|---|---|---|
| 请帮我预约本周六下午三点的线上试听 | trial_request；customer；current；完整原话 | 请求预约试听，期望时间保留原文；不生成约定 |
| 我想了解一下试听课程 | trial_interest；customer；current | 试听意向，无预约请求 |
| 我没有说我想预约试听 | trial_request；customer；negated | 否定证据，不生成肯定请求 |
| 我之前说我想预约试听，但现在不约了 | trial_request；customer；negated | 撤回陈述保留，不自动删除历史请求 |
| 如果明天下午有空，我就预约试听 | trial_request；customer；conditional | 条件证据，不生成肯定请求 |
| 请顾问联系我，帮我预约明天下午的试听 | advisor_request与trial_request；customer；current | 两类独立请求，同消息各一次 |
| 我想报名你们的课程，请告诉我办理步骤 | enrollment_request；customer；current | 明确报名请求，不确认报名或付款 |

## 本地验收结果

- Sol真实提取11个中文样例通过；实际模型均为gpt-6.1-sol，样例不允许备用模型掩盖失败。兴趣、明确请求、否定、撤回、引用、条件、多诉求及报名边界均有覆盖。
- 中文PC两条带时间的自然表达完成实际对话→服务端提取→CRM列表／原文闭环。各1条试听请求，0条新任务、0条客户约定。十次重复处理不增加请求或通知事件。
- 发布白名单源码完整检查：1134通过、16项条件跳过、0失败；类型检查、构建和差异格式检查通过。早期本地受限HTTP检查不作为完整发布回归结果。
- 原有其他客户、员工、任务期限、配置与历史通知核对一致。本轮仅在授权的合成样本上追加验收记录；不重放历史通知。
