# Lead列表筛选

常用区依次为搜索、负责人、销售阶段、首次联系、更多筛选。集合管理模式复用CrmSingleSelect，不增加左侧导航。高级区按互动与跟进、销售进展、学习需求分组，只展示已实现的条件。未增加居住地、里程碑、客户约定和三条互动时间范围查询。

所有条件均选择后立即更新结果与人数，包括高级筛选的多选、取消选中和清空。多选弹出层与高级面板保持展开，完成按钮只关闭选项层，不承担应用或保存职责。不再提供应用筛选或取消按钮。同一条件多选为OR，不同条件为AND；已选条件始终可见，可逐项移除。

“清空条件”清除搜索、负责人、首次联系和各维度，保持排序与视图；“恢复默认”恢复角色默认负责人和默认排序，不改变视图。服务端权限始终独立生效，“全部可见客户”不扩大可见范围。默认不使用“需处理”隐含范围。

销售阶段仅列现行七阶段与未填写，不将旧阶段映射为新阶段。最近销售联系结果读取三条互动时间线中的sales.result，不能读取可能过期的profile.connectStatus；客户主动回应不冒充销售主动联系。暂无销售联系记录与已记录的未接通／未回复不同。联系概况沿用contactOverview的时间阈值；仅提供客观查询，不产生催办、任务或Tier变化。尚无销售联系以sales时间线无记录判断，不以是否完成首次要求代替。

客户诉求／意向与列表worklistIntents同源，排除无依据标签、已修正证据和测评完成等事实事件；有真实联系／对话依据时优先使用，否则按已有问卷关注展示口径查询。暂无有依据的信息只表示当前证据不足，不推断客户没有意愿。

首次联系保留现有计时和日期口径；“已完成或无首次联系要求”目前仍是一个合并条件，不伪称已拆分。时间边界按配置运营时区计算，不改变任务期限。排序与筛选独立；当前“最近动态记录”和“处理优先级”沿用原排序逻辑，不解释为AI推荐。

本轮不提供历史兼容入口。筛选偏好恢复时清理已删除选项，不迁移或修改业务数据。默认在3000验证中文电脑端；清理、其他语言验证、通知实发与发布范围分别依用户当次授权。本轮结果见acceptance/20261026-revalidation-results.md。

桌面更多筛选的五个条件同一行展示，不显示占高的分组标题和规则说明段落；规则说明保留在更多筛选按钮提示中，语义分组保留给无障碍工具。空间不足允许换行，详情左侧保持单列。

筛选查询开始不清空当前已授权列表、统计或上次刷新时间，保留内容直到新结果返回，再替换结果；轻量更新中状态预留位置，列表以aria-busy标明正在更新。筛选框和选项层不卸载。旧查询响应保持取消隔离，访问权限失效或授权变更仍立即清除旧数据，不能为避免闪烁保留无权数据。

详情左侧默认仅显示搜索、筛选按钮和结果数量；按钮计数包含当前全部条件。展开后查看与修改完整条件，立即查询；列表与详情共用筛选状态，不重置选择。展开面板作为有高度限制的卷帘浮层覆盖名字列表并独立滚动，不推移客户列表；点击外部或Escape收起；收起不清除条件。排序及恢复默认在展开时显示。

Lead详情桌面列表保持展开，不提供收起客户列表按钮；原有窄屏列表／详情切换能力保留。本轮不测试窄屏。

左侧标题合并匹配人数（客户 · N），筛选下方不重复显示匹配人数；更新状态放在标题旁。浮层按当前屏幕底部可用空间动态计算高度，最高680px，保留16px底部余量。恢复默认筛选会恢复角色默认条件与排序，清空条件仅清筛选，均保留当前视图、不改业务数据。
