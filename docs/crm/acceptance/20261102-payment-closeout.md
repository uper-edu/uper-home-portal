# 收款核验：历史准确性、退款事实、状态与财务入口收口

2026-11-02，本地3000中文电脑端。本轮依据用户确认的整体评审继续实施；用户另行确认授权财务可登记实际退款，以及仅模拟数据的临时隔离验收。后续确认移除报名依据重复入口、补充销售信息、点行看详情与行末下一步操作，以及纯财务默认进入清单。

## 最终行为

- 清单：客户名称支持键盘进入详情；点击行内非交互区域也打开详情。文字选择、按钮和其他控件不触发行导航。行末按现有记录显示核验付款、核验退款或核实到账；已收齐／无需收款且无待核验项不再提示收款操作。
- 快捷核验使用重新加载并授权的本项目原记录。只选择所请求类型中最早登记的待核验款项；项目、类型或状态变化时回当前历史提示核对，不静默切到另一种款项。实际到账／退款时间仍由财务明确输入，不预填。
- 返回保留筛选、分页和位置／触发焦点。取消编辑回详情，地址恢复view，避免刷新再次进入receive表单。带草稿使用共享离开确认，继续编辑不丢输入，放弃不保存。
- 详情：课程／课时旁有明确状态；课程下紧凑显示当前销售负责人、报名确认时间，原报名经办人与当前负责人不同时补充经办人。不显示重复的“查看报名依据”；原basis及历史保留，不删数据。
- 状态与金额：未收款／无需收款中性，部分收款蓝，已收齐绿，应收未确定与待核验琥珀；待核验与项目状态分别表达。正常剩余应收蓝，已收齐的0绿，超收琥珀并展示超收数额。不从余额推断逾期。清单与详情复用同一状态组件与语义变量。
- 支付历史按实际时间倒序；每笔金额、时间、渠道、原文、图片、登记／核验／作废人员与时刻仍可追溯。详情与凭证统一展开；作废收在各笔更多操作，必须填写原因，菜单支持外部点击与Esc关闭。已收齐的额外到账也收在项目更多操作中。
- 修正错误：原登记600,000、核实500,000后作废，摘要保持核实500,000和实际时刻，注明已作废／不计汇总；原600,000及原登记时刻保留在依据中，不恢复成核实前值。
- 授权财务可登记已实际完成的退款：金额、实际时间、方式、去向、交易／收据编号及原因必填，可保存私有原件图片；不能超过当前净收款，有待核验退款须先核对原记录。保存使用原事务／幂等／版本／权限及结果查询保护，不调用支付网关、不代表退款审批、不调整约定应收。
- 账户用途：入账明确公司收款银行／钱包／商户账户，退款明确客户账户或接收人。新记录保存accountRole用途并由服务端按实际操作／款项类型校验；旧记录不回填用途，以原记录中性名称保留，不能把旧账号直接推断成公司或客户账户。切换登记类型清理另一种用途的账户草稿，避免串用。
- 有退款时呈现累计到账－退款＝净收款，并说明退课／合同变更需另行确认；剩余应收继续按原约定计算，不自动作商业调整。
- 财务默认入口按实际能力判断，不看角色名字猜权限。CRM仅有客户查看和收款核验职责时，无模块参数的/crm默认收款核验；浏览器回到/crm使用同一规则。明确客户、款项、文档链接保留。兼具销售、经理或运营职责的账号保持原默认入口。
