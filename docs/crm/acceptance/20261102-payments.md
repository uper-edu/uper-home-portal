# 客户付款与到账核验：本地验收

日期：2026-11-02。范围：本地3000；用户明确授权的临时模拟库、模拟员工及模拟客户。未推送GitHub、未部署测试或生产服务器。

## 结论

本地已接通“报名项目及约定应收 → 销售登记付款／退款 → 财务或明确授权经理核验 → 余额与活动汇总 → 退回／更正／作废历史”。旧Paid、登记金额及客户预算均不作为实际到账证明。没有自动修改销售阶段、Tier、负责人、任务或通知。

入口：客户详情页头“报名与收款”。核验采用独立权限 `crm.payments.verify`，不从经理名称或普通销售编辑权限推定。本轮保护现有权限，未向任何真实角色或员工自动授权；正式使用前由系统管理员明确授权财务或指定经理及客户范围。

运行包：`4c207d8c967b-7daf8f3a5dfa32d4`，前后端版本一致。此为当前本地工作区构建，不代表GitHub已同步；既有并行改动保留，本轮没有提交它们。

## 完成的业务行为

- 项目约定应收独立于客户学习预算；留空是尚未确定，0是无需收款。
- 销售登记每笔实际付款／退款的金额、时间、方式及原始说明，状态待核验，不计入已到账。
- 核验须填写实际金额、实际时间、银行／支付账户标识、流水号及核验依据。可核实不同于原登记的实际金额，原金额、原流水、原文和历史保留。
- 独立计算已核实收款、退款、净收款、剩余应收和超收；未知应收不判已收齐。退款不自动减少合同应收，合同变化须由授权人员更正项目并填写原因。
- 待核验可退回；核实误记可说明原因后作废。原始记录和前后值保留，不能直接删除已核实事实。
- 对账户与流水号归一化后做全局唯一约束，跨项目、跨客户重复核验拒绝。退款不能超过该项目净收款；作废不能造成负净收款。
- 客户与Campaign收款汇总和旧登记金额分开；已合并客户的账本、原始依据、历史及来源保留，按原项目客户来源归因而不重复计数。此为来源客户群统计，不是广告因果归因或ROI。
- 每次写入及结果查询重新核对员工权限、客户范围；版本冲突保留输入。事务失败回滚；结果未知只查询原请求，不自动重提。浏览器仅按员工和客户保存待查询编号，不持久保存财务原文。

1. 全量默认回归：1499项，1469通过、0失败、30跳过。与 `npm test` 相同的Node测试命令执行；临时HTTP模拟需要本机监听权限。

3. 金额、时间和Campaign来源纯逻辑专项：3通过；亦包含在全量默认回归中。
4. TypeScript检查（`npm run lint`对应命令）通过；本地dev构建通过；`git diff --check`通过。

12项隔离专项覆盖：

- 空账本和旧Paid／金额不被当作已核实，授权与未授权读取。
- 项目和待核验提交保存、原文一致、相同请求幂等。
- 销售核验拒绝、旧版本冲突、跨项目引用拒绝。
- 登记60万而实际核实50万，原金额、原流水、原文保留；部分付款余额；保存结果按员工及客户隔离。
- 账户与流水号归一化、跨客户重复核验拒绝。
- 同版本并发只成功一次、全额付款、退款与余额。
- 超额退款、非法金额、无明确偏移时间拒绝；退回及作废历史保留。
- 项目应收更正仅授权人员可执行，未知应收不判付清。
- 财务权限撤销和客户转交后即时拒绝写入／结果查询。
- 写入后注入失败整笔回滚；客户原资料、原期限及通知队列不变。
- 已合并身份账本与汇总保留；列表不暴露银行资料。
- 实际HTTP入口未登录、客户范围、来源限制、保存及只查询回执恢复。

### 30项跳过的含义

默认全量命令没有设置独立MySQL授权变量，因此30个需隔离库的测试入口按设计跳过；不是30个失败，也不能称它们本轮全数通过。其中收款入口已由上述12项独立专项补齐。其余29个入口涉及备份恢复、自动分案／补分、营销活动及推广、AI切换、互动时间线、原有联系与约定、身份、通知、注册等既有模块，本轮没有重跑其全部数据库验收。此次保护性检查和收款专项不替代这些模块的独立验收；未来发布应按实际发布清单和受影响模块核对相应证据。
