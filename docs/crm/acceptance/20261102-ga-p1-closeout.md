## P1-1 匿名顾问请求漏计

原问题：匿名申请先保存消息并返回contact_required；之后登记事务会关联请求事实，但登记回执只携带客户资料，因此客户端没有确认依据可补记advisor_request。

修复：

1. 登记事务从原有待关联消息中收集本次新确认的handoff请求，返回最小`advisorRequests`回执，并与原登记回执一起持久化。原文、来源关系、请求事实及通知事件仍走原事务。
2. 已recorded／review_required的请求不作为新请求返回；普通资料再登记不扫描历史补报。booking、enrollment保留原业务处理，不冒充顾问请求。
3. 结果查询和相同提交重试返回同一持久回执。旧回执没有该字段时仍可读取，不补造历史数据。
4. 客户端须先通过原访客范围及登记保存回执校验，再检查请求所属客户、action、状态和操作结果；与直接申请共用原消息ID去重。客户ID和消息ID只在本地校验、去重，不上传GA。

## P1-2 CRM登录切换DOM异常

触发链：`AdminRequiredNote`原先向React管理的纯文字标题创建Portal；切换语言时标题的textContent被替换，附加节点被移除，登录表单卸载时Portal再次移除该节点，触发NotFoundError。先前无观察浮层的页面也能复现，因此不是验收浮层证据，更不能仅凭错误提示将原因归为浏览器翻译。

修复：给共享必填说明增加显式inline模式，登录及修改本人密码标题直接拥有说明节点；标题文本和说明分别由React渲染，不再向这些标题创建外部Portal。保留原说明样式、必填校验、登录／密码保存处理和权限逻辑。没有借此迁移所有其它表单。

中文桌面实际验证：

- 新访客首次加载后切到中文，再登录模拟经理：成功，无错误页面或控制台DOM异常。
- 空必填：拦截并聚焦缺项；错误凭据：保留输入、显示原错误，未进入工作区。
- 经理进入工作区后打开并关闭本人密码表单：正常；未填写或更改密码。
- 退出，再登录模拟销售：正常；销售不出现经理的销售运营入口，未扩大权限。
- 不含观察浮层的原始页面再次“切中文→经理登录”：成功，控制台错误为0。
- 最终3000沿用现有登录会话打开中文客户列表：正常，控制台错误为0；未退出真实账号、未使用或重置真实密码。
