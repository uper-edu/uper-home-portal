# 备份、恢复与迁移核对验收

2026-10-12。本轮只对独立测试 PostgreSQL（5448）写入，使用模拟客户；真实 CRM（5449）的核对为只读。没有部署、推送 GitHub 或执行真实数据迁移。

## 修复内容

- 备份覆盖当前 17 张业务表，包括新增 `hsk_attempts`。旧 16 表结构仍可备份；源库出现未知表时拒绝，防止静默漏备。
- 备份本身不运行数据库迁移；使用只读一致性快照。保留 PostgreSQL 时间戳微秒精度，整份 v2 备份校验完整性，原子写文件并设权限 0600。
- 恢复验证表清单和字段，拒绝非空目标库，按外键顺序入库；发生后段外键错误时事务整体回滚。恢复自增序列及消息序列，避免新写入碰撞。v1 兼容恢复明确说明原备份没有 HSK 独立表数据。
- 迁移 dry-run 列出数量、源文件校验、重复联系方式候选与逐条异常。未知消息时间使用有明确标记的占位时间，原始 ID、原始时间及顺序保留，不借用客户提交时间伪装成消息时间。
- 保存迁移来源指纹；相同文件再次导入跳过已有客户，保留切换后的新跟进。修改过的来源或与目标客户 ID 冲突时拒绝，不追加到无关客户。无来源指纹的早期导入需人工核对后处理。

## 数据核对结果

最终源测试库为 `uper_backup_acceptance_20261012_isolation`。备份包含 3 个模拟客户、16 条消息、1 条 HSK 记录、1 条模型尝试、3 个任务和对应通知/配置记录，17 表均核对。模拟源及备份、逐表校验和详细日志保存在 Git 忽略目录 `.local-backups/backup-acceptance-20261012/`，权限 0600；不上传客户数据或备份。

真实 CRM 保护证据：第一轮较长窗口发生并行 HSK 活动，HSK 记录、客户资料和关联通知变化；因此不能宣称整个工作时段全库未变。原客户 JSON 文件保持不变，本轮模拟客户 ID 在真实库中为 0。随后以新空测试库完整复跑，紧邻验收前后的真实 17 表及客户文件 SHA-256 全部一致。没有为消除差异而回滚真实业务或删记录。

## 仍未验证与发布限制

1. 本机应用层恢复已通过；未来部署主机的 `pg_dump` / `pg_restore`、角色、扩展及完整数据库基础设施恢复尚未验收。本机未找到这些原生 CLI，未安装或声称验证通过。
2. 自动备份周期、保留期、异地副本及恢复告警尚未配置；应用层 SHA-256 只检查损坏，不代替加密、访问控制或可信签名。
3. 历史未知日期和重复联系方式仍需人工确认；未知时间展示已在后续独立验收中修复，见 `docs/crm-unknown-message-time-acceptance-20261012.md`；无原时间证据的历史记录继续保持未知。migration_hold 任务应逐条审阅后激活，不能批量重算截止时间或触发历史通知。
4. v1 备份缺少的 HSK 数据无法凭空补回。旧导入没有来源指纹时，不自动认可再次导入；需先核对已有数据及来源。
5. 真实数据切换、真实教育平台权限联调及部署验收未在本轮执行。恢复数据库应先隔离外发，核对已发送/结果未知记录，再启用 Worker；不得从已接受新写入的数据库直接回到旧 JSON。
