# CRM 历史消息未知时间显示修复与验收

2026-10-12。只用独立测试库与模拟客户验收；未执行真实 CRM 数据迁移、后端重启、GitHub 同步或公网部署。

## 根因与行为

CRM 列表接口此前直接使用 `messages.created_at` 作为聊天时间，其中旧导入可能是 epoch 占位或借用留资日期。详情接口返回的原始数据库行又没有统一的显示时间。客户旅程使用 `msg.timestamp || lead.submittedAt`，因此缺失消息时间也会被伪装成留资时间。

新增共享时间解析器：历史消息只依据原始时间元数据或明确的可信标记确定显示时间；缺失、无效或明确标记未知的时间，返回空显示时间及 `timestampKnown=false`。保留原始存储时间、原始时间字符串和错误/迁移元数据，GET 请求不改写数据库。

列表、详情与客户卡片链接使用同一规范。进线对话及客户旅程显示“未知时间 / Unknown time”，不填入留资日期。未知旅程消息位于有日期的事件之后，相互之间保留原顺序；进线对话保持全部消息原顺序。有原始证据的真实日期，包括真正有效的 epoch 时间，继续显示，避免按日期数值一刀切删除真实信息。
