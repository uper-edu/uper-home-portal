# CRM 跟进任务统一展示与操作验收

日期：2026-10-17。范围：独立本地 MySQL / `127.0.0.1:4426`，仅模拟数据；未切换 3000、未推送 GitHub、未部署服务器。

## 交付行为

| 位置 | 展示与操作 |
| --- | --- |
| 工作列表 | 保留下一步动作、对应时间和额外任务数量；使用共同时间投影 |
| 四页签上方 | 仅下一步摘要、语义化时间、运营时区及“查看任务”入口 |
| Follow-up | 唯一完整任务列表；当前任务提供“记录跟进”，更多菜单集中补充、改期、替代、取消；已完成与取消任务进入历史区 |
| Conversations | 保留原消息及新建／补充的真实事件含义，仅显示任务名称与当前状态的引用；点击进入 Follow-up 对应任务 |
| Profile / Assessment | 不新增任务列表；共用顶部摘要与查看入口 |

从任务进入沿用同一结果表单，仅预选该任务；普通记录默认不完成任何任务。随手记录继续独立保存，不增加联系统计、不完成任务。历史任务提供查看处理记录，不显示可再次处理的主按钮。

时间同时区分响应截止、约定执行、内部复查及改约执行。改约时间与原响应截止分别显示，不覆盖原期限，不消除逾期事实。历史占位日期继续标记待确认，不显示为真实截止。

## 浏览器与持久化验收

使用模拟 Fadhil / Sales，样本与已有独立库记录隔离。新建样本用于验证界面和操作持久化；其初始任务、消息由显式 fixture 创建，不把它们声称为真实 Chat 自动触发证据。

| 场景 | 结果 |
| --- | --- |
| 三个开放任务及一项历史任务 | Follow-up 只有一套完整列表；顶部计数与当前任务数一致 |
| 从对话的预约引用按 Enter | 跳转 Follow-up、聚焦对应任务；点击记录跟进仅预选该预约，保留正确客户原话 |
| 返回对话 | 恢复原会话及原消息定位，不按相邻文字猜测关联 |
| 补充依据 | 增加 `task.supplement` 事实，不改变原动作和截止时间 |
| 改期 | 单独保存 2026-10-22 14:00 Asia/Jakarta；保留原响应截止及逾期状态 |
| 随手记录 | 增加 `information.recorded`，当时开放任务仍为三项、人工联系次数仍为零 |
| 保存人工双向联系并完成预约 | 仅预约变为 completed；另外两个任务仍 open，期限未变；最终只有一条联系记录、一次联系尝试 |
| 已完成预约的对话引用 | 显示当前“已完成”，跳入展开的历史任务；可查看关联补充、改期及联系记录，无“记录跟进”主按钮 |
| 未认领共享池客户 | 销售可查看引用与任务；新增、更多操作及记录跟进不可用，不扩大写入权限 |
| 后台五秒刷新 | 摘要仍保留改约执行和原响应截止，未退回缺少字段的旧投影 |

数据库只读断言通过：原预约 `due_at` / `original_due_at` 与建样本时完全一致；改约写入独立 `scheduled_at`；四条任务最终为两个开放、两个已完成。客户归属、分组、阶段及两条对话原文保持一致。

## 三语、布局和键盘

- 英文、印尼文、中文统一更新摘要、任务卡、任务引用、表单任务清单及在线手册；姓名、动作、人工备注和消息原文不翻译。
- 浏览器请求 390 / 768 / 1280 三档测试，当前浏览器缩放下实测 CSS 宽度为 354 / 698 / 1163px；九组均无整页横向溢出，窄屏按钮换行、动作和期限完整可读。
- 主处理按钮高度约 44 CSS px；浅色与深色走查通过。当前逾期使用红色文字，完成使用绿色状态，主要操作使用青绿色。
- Enter 可激活任务引用和查看任务；任务跳转与返回原文有焦点定位。此为内部模拟与键盘抽查，不等同于完整无障碍认证或真实销售效率验收。

## 修复的回归问题

1. 发现选中客户的定时刷新会遗漏新增时间字段，摘要数秒后丢失改约时间。列表、刷新、通知定位及处理入口现共用任务投影，并增加回归检查。
2. 保留已关闭客户历史待确认任务的原有排除规则，避免展示合并改变计数或业务范围。
3. 完成任务和未知日期分别处理，避免已完成任务仍呈现红色逾期操作、历史占位日期被误认为真实截止。
