## 1. 发布前准备

1. 锁定获批提交和范围。审查启动迁移、初始化和历史数据影响。涉及 Enrollment 时，销售与财务核对新报名、凭证、核款、退款和商机的验收证据。已上线的旧款项按原记录核对。
2. 对最终待同步版本完成 `npm test`、`npm run lint`、`npm run build` 和 `git diff --check`。另执行 `npm run build:prod` 生成正式制品，记录提交、构建编号和校验值。保留上一版制品。
3. 按正式环境部署方式核对域名、代理、TLS、数据库和运行配置。已有私有配置只补缺项，保留现有值及有意留空项。凭证和解密密钥保存在正式私有配置及受控备份中。
4. 备份数据库、运行配置和凭证解密所需密钥，记录恢复证据。对照允许变更范围记录账号权限、客户归属、报名、实收和退款余额及队列基线。涉及结构和数据变更时，先在获准的隔离环境验证升级及回退。
5. 按批准的窗口暂停受影响写入和队列消费。记录在途发送及恢复条件，完成下表中适用的配置核对。

## 2. 系统默认配置检查表

对存量环境优先核对实际生效值及来源。新库检查初始化结果及重复执行。表里的默认值和核对目标供验收使用，存量差异交对应负责人确认。

从正式官网开始核对公开入口，再用相应权限账号进入后台。按下列顺序检查，记录实际生效值、来源与结果。

| 顺序与检查项 | 访问路径 | 核对内容 |
| --- | --- | --- |
| [ ] 01 环境及域名 | **服务器** → 正式应用运行配置；**浏览器** → `https://uperedu.com/api/version` | 核对前后端制品、正式数据库和 `PORTAL_PUBLIC_ORIGIN=https://uperedu.com`。数据库和变量来源由运维从运行配置确认。正式应用使用经批准的内网 MySQL TCP 直连，`MYSQL_TLS_MODE=disabled`。本机 socket 和 TLS CA 配置不适用于这条正式应用连接。 |

| [ ] 03 课程定价 | **CRM** → **报名管理** → 标题右侧 **课程与班次设置** → **课程与报价** | 核对课程级别、标准学费、优惠范围和启用状态。 |

| [ ] 07 发信池及 Enrollment 选用 | **系统管理** → **邮件配置** → **发信池** → **Enrollment · Production**；再到 **CRM** → **报名管理** → **课程与班次设置** → **招生邮件** | 先核对池启用状态、成员、负载分配策略、账号及池限额。池日上限留空时不限。再核对招生实际选用的池、固定发件账号规则及发送记录。已有绑定由系统管理员核对。 |
| [ ] 08 Lark | **CRM** → **销售运营** → **通知与审计** → **通知渠道**，再查看 **通知策略** 和 **接入检查**；**Lark 开发者控制台** → **CRM-Bot** → 核对已发布版本的回调；**服务器** → 私有运行配置 | 核对群 Webhook、个人绑定回调、群和个人发送模式、策略收件范围及管理层群。查看消息链接的访问权限。 |
| [ ] 09 后台及 GA | **服务器** → 正式应用运行配置和进程状态；**Google Analytics** → **UPER Production** → 对应 Web 数据流 | 核对后台的实际运行状态、正式衡量 ID 和本次批准的外发状态。发布后按签核顺序恢复后台和外发。 |
| [ ] 10 公开入口 | **官网首页** → 一级导航 **课程报名**；另从 **/link** → **查看课程与报名** | 核对正式域名、课程目录、语言和推广来源保留、WhatsApp 联系入口。目标班次使用正式资料。 |

## 3. 生产环境变量

按用途列出生产模板中的变量。表中填写的是配置说明，私有值由运维通过正式应用的运行配置提供。

### 运行环境与站点

| 变量 | 用途与配置时机 |
| --- | --- |
| `PORTAL_ENV` | 选择 dev、test 或 prod。后端读取对应私有文件，部署时也用它校验构建包目标。 模板值为 `prod`。 |
| `PORTAL_ENV_SOURCE` | **按需**。部署系统注入完整环境时设为 `injected`，由启动器读取私有环境文件时省略。 模板值为 `injected`。 |
| `PORTAL_DEPLOYMENT` | 选择公司测试或正式站的部署校验规则；常规本地开发留空。 模板值为 `production`。 |
| `PORTAL_PRODUCTION_READY` | 正式站启动门禁。完成正式环境配置和验收后才设为 true。 模板值为 `false`。 |
| `NODE_ENV` | 控制 Node.js 及依赖的开发／生产运行模式。 模板值为 `production`。 |
| `APP_ENV` | 标识应用运行场景，本地通常用 local；测试站和正式站用 production，以启用对应的访问保护。 模板值为 `production`。 |
| `PLATFORM_MODE` | 选择员工身份来源。local 使用本站员工账号；mock 仅供隔离测试使用。 模板值为 `local`。 |
| `PORT` | 后端监听端口。本地通常为 3000，部署时由容器和反向代理约定。 模板值为 `8080`。 |
| `APP_URL` | 站点对外访问的主地址，用于生成站内链接及站点元信息；部署时须符合环境校验。 模板值为 `https://uperedu.com`。 |
| `PORTAL_PUBLIC_ORIGIN` | 生成招生邮件中的公开链接及验证回跳地址。发布前核对正式 HTTPS 域名。 模板值为 `https://uperedu.com`。 |
| `TRIAL_FRONTEND_DIRECTORY` | 后端提供静态页面时读取的前端构建目录，填写当前环境的实际路径。 |
| `PORTAL_LOG_LEVEL` | **按需**。需要调整日志级别时配置，接受程序默认值时可省略。 模板值为 `info`。 |

### MySQL 与数据库工具

| 变量 | 用途与配置时机 |
| --- | --- |
| `PORTAL_DATABASE_DRIVER` | 选择后端数据库驱动。当前 CRM、CMS 的 MySQL 运行方式使用 mysql。 模板值为 `mysql`。 |
| `TRIAL_DATASET` | 数据库安全场景标识。local-crm 用于本地 CRM；部署使用 synthetic 标识以通过当前校验，它不会初始化或清除数据。 模板值为 `synthetic`。 |
| `MYSQL_TRIAL_URL` | MySQL 连接地址，包含数据库账号、密码、主机和库名。只在对应环境的私有配置填写。 |
| `MYSQL_TLS_MODE` | 正式应用使用经批准的内网 MySQL TCP 直连，启动校验要求 disabled。 模板值为 `disabled`。 |
| `MYSQL_BIN_DIRECTORY` | **按需**。仅在备份或恢复工具无法从系统路径找到 MySQL 客户端时指定其目录。 |

### 员工登录、权限与访问保护

| 变量 | 用途与配置时机 |
| --- | --- |
| `ACCESS_OPERATION_KEY` | 为账号恢复和受保护操作签名的服务端密钥，部署时至少 32 字符，按环境独立保管。 |
| `ACCESS_PUBLIC_ORIGIN` | 指定受保护访问的主站点来源，部署时填写对应的规范 HTTPS 地址。 模板值为 `https://uperedu.com`。 |
| `ACCESS_ALLOWED_ORIGINS` | 允许访问受保护页面和接口的 HTTPS 来源清单，用逗号分隔。 模板值为 `https://uperedu.com,https://www.uperedu.com,https://home.uperedu.com`。 |
| `ACCESS_TRUSTED_PROXIES` | 填写可信反向代理的具体私网 IP，用逗号分隔；用于判断代理传入的连接信息。 |

### 招生邮件

| 变量 | 用途与配置时机 |
| --- | --- |

## 4. 软件系统默认设置

以下是应用初始化值或新建时的默认值。发布时按第 2 节的入口核对后台已保存的实际配置。升级保留既有配置，差异由配置负责人确认。

| 设置 | 默认值与业务含义 |
| --- | --- |
| 报名期限 | 获席后 24 小时内付款并提交凭证。已付款学员的顺延或转班邀请默认 48 小时答复。修改全局规则只影响新生成的截止时间。 |
| 招生邮件 | 初始招生发信开关关闭，默认启用同一报名邮箱固定发件账号。正式启用前在招生邮件页确认选中的生产池。 |
| 发信池 | 新建池默认启用，日上限留空时不限，默认按额度均衡。 |
| 发件账号 | 新建默认启用，SMTP 默认 Lark 主机及 465 端口，每日 450 封、每日 200 个去重外部收件人，月限额留空，频率默认 200 封／100 秒。核对服务商实际限额后配置。 |
| Lark 群与个人渠道 | 新初始化的系统渠道默认真实发送。存量发送模式以已保存配置和已批准的首次升级迁移结果为准。恢复后台前核对目标及收件范围。 |
| 课程与报名班次 | 课程、报价、每周课表、收款资料和发布状态按正式招生资料核对。标准班 10 人足额到账确认开班，招生上限 15 人。小班 4 人足额到账确认开班，上限 6 人。 |
| 账号和权限 | 核对预置角色和实际生效权限。新初始化账号执行首次登录改密，存量账号和授权保持原记录。 |

## 5. 切换与放行

1. 使用已登记的正式站部署操作切换到目标制品。按演练顺序执行迁移和初始化，记录完成时间及影响。核对 `/api/health` 和 `/api/version`，确认前后端版本一致、数据库正确、日志无启动异常。
2. 恢复邮件消费前，按 [旧队列操作清单](requirements/enrollment-mail.md#发布前旧队列操作清单)备份并审核事件键。命令先预览，确认后以同一组键加 `--apply`。核对未发旧件、有效报名成功邮件、模拟回执及保留项，再预览确认新增为零。正式运行前验证清理脚本可从目标源码和运行配置执行。
3. 销售、财务和管理员分别只读抽查入口、权限和存量记录。经另行授权的测试写入或真实发信按批准场景、账号及收件地址验收。发信获准后核对发件人、实际收件和邮箱验证回跳。
4. 由放行人签核差异、队列处置和观察安排。按批准顺序恢复写入、后台及各渠道消费，观察错误、重复投递、账务和积压，记录结果。

## 6. 停止与回退

健康或版本不一致、关键权限异常、金额差异、迁移失败或误发时，停止放行并隔离受影响的写入或外发，保留日志、记录编号和发送回执。确认旧应用兼容当前数据库后方可回切旧制品。需要恢复数据库时，由回退决策人批准恢复点，先登记切换后的新增业务及对账安排，防止恢复覆盖已发生的收付款。回退后复核健康、版本、账务和队列状态。

招生放行前，在「报名管理 → 课程与班次设置 → 报名规则」核对正式收款账户，在「招生邮件」核对发信池和招生就绪提示。先保持 `PORTAL_ENROLLMENT_ACCEPTING_NEW=false` 验证存量订单链路，再在获准开放后启用新报名。暂停时保留 `PORTAL_ENROLLMENT_SERVICE_ENABLED=true`，使已有订单仍可正常处理。就绪提示核对保存的配置，正式 SMTP 的实际投递另行联调。
