# Follow-up 三个内容区与按需处理区验收

日期：2026-10-17。范围：仅独立 4426 服务、隔离 MySQL 与模拟销售。本轮没有切换本地 3000、推送 GitHub 或部署服务器。

## 交付内容

1. **当前情况**：联系安排优先；最近有效人工沟通与更新的未接通尝试分开；人工原文保持不变，长记录按需展开。客户人工备注独立保留。待核实动态只在有内容时出现。身份候选核实移入 Profile，仍沿用原权限和接口。
2. **跟进任务**：仅一套完整待办列表；动作、状态、约定执行时间／响应截止／内部复查时间保持可见。任务依据与精确客户原话按需展开。处理任务聚焦当前事项，其他任务可展开查看。改期、补充、替代、取消仍使用原接口和规则。
3. **跟进记录**：事实记录和原时间轴合并呈现，筛选紧邻列表；仅使用已保存的 log ID 合并同一条联系记录，不按相似文本去重。已完成任务进入历史任务区；较长历史先展示20条，可继续加载展示。详细审计数据与原文保留。
4. **按需处理区**：记录联系、记一条信息和任务操作共用编辑区域，同一时间只打开一种业务表单。普通记录不预选完成任务；从任务打开只预选对应任务。随手记录不增加联系次数、不完成任务。
5. **草稿与定位**：切换操作、页签、客户和跳到完整对话前检查草稿；保存校验失败保留原输入。话术关闭增加放弃确认，客户语言/模板原有覆盖确认保留。原文预览不离开编辑区；完整对话按保存的会话与消息 ID 定位，兼容请求 ID 引用。
6. EN／ID／ZH 界面及《系统说明》《操作指南》同步更新。保留原客户、任务和销售记录的输入语言。

## 验收结果

| 场景 | 结果 |
|---|---|
| 随手记录 → 尝试打开任务 → 继续编辑 | 出现草稿提示，原始文字保留；保存后仅新增 information.recorded |
| 独立信息保存 | 不创建联系日志、不增加触达次数、不完成任务 |
| 从预约任务进入联系表单 | 仅该任务预选；其他任务按需展示；完整期限仍可见 |

| 保存后跟进历史 | 一条联系事实与其旧日志合并展示一次；显示完成任务名称、保留安排及原话跳转 |

| 从联系表单切到新增任务 | 放弃确认后仅剩任务操作表单，没有两份编辑表单并存 |
| 三语切换 | 任务操作草稿原文不变；新增控件已翻译；人名和备注不翻译 |

| 共享池权限 | 未认领客户无处理任务按钮，记录、创建、调整入口禁用；未执行认领或权限修改 |
| 数据核对 | 原有行哈希全部保留；员工、权限、归属、配置、原消息、测评及原任务未被修改 |
