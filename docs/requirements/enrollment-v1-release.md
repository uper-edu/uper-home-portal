# Enrollment 首版放行范围与验收

首版交付从公开选班、邮箱验证、获席和转账开始，到财务核实到账、学员收到报名结果以及销售看到商机状态。班次达到足额到账人数后自动确认开班。开班后的调课、换老师、停课、补课和实际上课安排由教学老师和运营协调。

## 生效规则

- 标准班 10 人足额到账确认开班，招生上限 15 人。小班 4 人足额到账确认开班，上限 6 人。一对一由销售客服约课。已获席订单保留当时的应付金额、付款期限和收款账户。
- 首班样板为 HSK 1 周末线上标准班，23 节，每节 45 分钟。标准总价 Rp 1.150.000，优惠总价 Rp 920.000，每节优惠价 Rp 40.000。首批公开班次只采用已核实的课表、模板、教材及教师类型。尚缺运营答复的排期保持草稿或留在待录入清单。
- 核实足额到账后使用统一的「报名成功」邮件。学员的首课安排由教学老师和销售沟通。正式 Lark 通报、经营周报修正、复杂排课及原班顺延另行评审。
- 暂停新报名后仍允许查单、补交已发生转账的凭证、核款和已批准的退款。正常待付款的已有订单沿用个人付款期限。确认不开班单独关闭该班收款，保留补交凭证及售后入口。
- 销售可为授权商机发起协助报名及符合条件的转班邀请。财务只按实际银行流水核款。CRM Manager 决定退款，财务登记原路退款。涉及已开班特殊退款时，教学老师提供实际已交付课次。

## 放行验收表

| 验收 | 操作与预期结果 |
| --- | --- |
| 公开报名与获席 | 官网和 /link 直达；确认课程、课表及报价。最后一席并发时只成功一人。同一请求重试返回原订单。共用邮箱可区分不同学员。 |
| 协助报名 | 销售提交后不占席。学员验证指定邮箱并确认才获席，重复确认只返回同一订单。核款后原商机显示已报名。 |
| 凭证与核款 | 凭证提交进入待核实；部分到账登记实收及差额；足额到账后才显示报名成功。同一流水不可入两单。标准班第 10 人足额到账只确认一次开班。 |
| 关闭与售后 | 无凭证、无到账可自助取消；付款超时释放席位且历史仍可查。晚交凭证、自动冲抵、财务核款与既有退款继续按原规则执行。 |
| 权限 | 学员不能打开其他邮箱的订单。销售只能查看授权订单的核验结果；财务不能审批退款；CRM Manager 按既有权限决定。 |
| 招生门禁 | 正式收款资料或招生邮箱投递未就绪时无法获新席。暂停后保留既有订单服务及后台处理。既有订单的收款快照照常使用。 |
| 通知 | 使用模拟投递核对验证码、待付款、凭证回执和报名成功邮件。班次确认开班后没有额外学员开班邮件。旧队列按发布清单处理。 |

历史验收使用当时的样板价格、开班人数和构建号，作为历史证据保留。最终放行使用同一版本报告实际验证项与未验证项。正式银行资料、课程目录、退款公示、邮件配置与实际投递需在发布时核对。推送、部署和真实招生均单独授权。

## 本地 3000 验收结果

验收源码为 `79958a9`，运行构建为 `79958a904104-631e455fafdcfdc7`。暂停与开放使用同一构建和同一个本机数据库。恢复开放后，3000 继续使用模拟邮件。验收只写入带唯一标记的测试记录，并在结束后清理。

| 场景 | 实测结果 |
| --- | --- |
| 自助报名与核款 | 实际读取模拟邮箱验证码。两名学员共用一个邮箱仍分开建单。凭证重复提交只形成同一记录。Rp 780.000 部分到账后仍待补款，补足 Rp 140.000 显示报名成功。第 10 人足额到账仅确认一次开班。足额到账时，学员只收到一封报名成功邮件。 |
| 限席、权限和商机 | 最后一席并发仅一人获席，重试返回原订单。不同邮箱无法查看该订单。销售可看自己负责的订单状态与实收，其他销售无此记录，核款操作被拒绝。协助报名确认前无订单，确认后只建一单，足额到账后商机更新。 |
| 暂停和存量 | 暂停时拒绝创建新单，已有学员仍能验证邮箱、读取订单原收款账户、交凭证。财务可核款并登记已批准的原路退款。财务不能审批退款，CRM Manager 可以。 |
| 关闭订单与旧款冲抵 | 自助取消后关闭付款入口。逾期订单仍可补交凭证。财务核实原单 Rp 125.000 后，系统自动冲抵同一学员的新单，原流水和两边冲抵记录均可核查。 |
| 候补与需求通知 | 常驻模拟邮件进程处理三条合成队列记录。有效需求完成模拟投递，需求条件已改及班次已满的记录在创建投递尝试前取消。 |
| 中文桌面 | 从 /link 进入报名，核对 HSK 1 周末班 23 节、每节 45 分钟和 Rp 920.000。核对退款说明、一对一实际课程和教师类型进入 WhatsApp 预填，以及暂停时保留「我的报名」。仅检查 WhatsApp 链接，没有打开外部页面。 |

全量测试分两组运行，合计 1,745 通过、0 失败、37 跳过。跳过的用例需要独立数据库。类型检查、构建、SQL 查询清单和提交差异检查通过。本轮未重新验收独立 MySQL 空库或旧库、移动端、英文及印尼文页面、正式 SMTP 或真实 Lark 客户端。
