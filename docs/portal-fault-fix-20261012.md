## 修复结果

| 原缺陷 | 改动 | 复验 |
|---|---|---|
| 数据库断线使进程退出 | 连接池和借用连接错误监听、连接超时、损坏连接释放及失败清理；新增 `/api/portal/ready` 数据库就绪检查 | 真正禁止测试库连接并终止现有连接：请求返回 503；恢复数据库后，同一进程恢复 200，无需人工启动 |
| 保存失败仅提示网络异常，刷新丢字 | 两入口共享保存状态处理和草稿缓存；草稿按服务端访客摘要与入口隔离；显示未保存／保存待确认／已保存但回复失败或中断；支持原消息 ID 和原会话重试；流结束必须有最终完成事件 | 两入口的指定文字被数据库拒绝，显示未保存及 Retry／Coba lagi；刷新后文字仍在；撤除故障后点击原消息重试，真实 gpt-4o 回复成功，各仅保存一条用户消息 |
| 刷新消息反序 | 新增数据库单调消息序号；一次性回填旧测试记录，历史迁移的数字索引按数值排序；会话恢复、CRM 会话／列表和模型历史统一按序号读取；备份恢复同步序号生成器 | 浏览器两个入口刷新后问题在回复前；测试库全部用户／助手配对反序数为 0；恢复备份后下一序号高于已有最大值 |

失败或中断的助手消息可在会话锁下重新生成，保留原用户消息与助手 ID，失败尝试继续留存；完成请求返回已有回复，不重复生成。调用方用相同 ID 携带不同文字仍返回 409。
