## 购买信号核对

问卷“排期关注”保存为 Asked schedule。它在客户资料和筛选中属于 buyingSignals，但时间轴正确标为“问卷关注内容”。第二次销售记录主动选择 Asked price，原文、操作者、时间、来源客户消息及处理任务一起保存；时间轴显示“员工记录的购买信号 · 询问学费”。资料汇总保留 Asked schedule 与 Asked price 两项。

实际 Chat “我要报名”创建了 enrollment 任务，但没有把 buyingSignal 更新为 Ready to enroll。普通自由对话也没有自动抽取购买信号。

## 发现的问题及边界

1. **关注内容与实际咨询混在同一汇总字段。** 时间轴已区分来源，但资料页及筛选仍统称购买信号，可能把问卷兴趣误读为实际询问。
2. **弱兴趣影响强意向分组。** 本次仅问卷选择排期即变为 Hot。当前 R1 对非 None yet 的单个 buyingSignal 判为 Hot，另有更高优先级的无回复规则；本轮未修改分类。
3. **明确请求与购买信号两条链路未统一。** 报名请求任务存在，不代表 profile 的 Ready to enroll 自动存在；销售不能仅靠购买信号筛选找全报名请求。
4. **时间轴仍有语义重复。** 同一次明确请求同时展示客户原文和“请求依据”，测评亦同时出现提交事实与定级记录。任务没有重复，但阅读仍可进一步压缩。
5. **通知未做本轮实发验收。** Worker 关闭、通知为模拟隔离设置；没有向真实 Lark 发消息，没有重放历史通知。管理者界面曾显示 13 项通知异常提示，本轮未改配置、未把它当成已修复或实收通过。
6. **活动自定义日期输入仍需单独复核。** 创建后卡片为默认 2026-10-17 09:00–10:00；本轮没有证明浏览器自动填入的其他日期已成功提交，不能据此确认日期控件存在产品缺陷，也不能宣称自定义日期验收通过。
7. 本轮走查为中文及一个模拟销售角色，不等同于全角色权限矩阵、三语全量回归或真实销售可用性验收。
