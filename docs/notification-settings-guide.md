# 通知设置与发送审计

## 页面定位与保存边界

本区域位于 CRM 的 SLA & Policy 下，与现有设置共用圆角卡片、标题图标、浅色/深色主题、分组字段及主色按钮。销售在 Leads 列表处理未读活动、归属和跟进；此区域供拥有 `notifications.manage` 的人员配置通知和排查异常。当前平台适配仍为本地模拟身份，真实主管/管理员角色划分待平台联调。

上方“保存配置 / 恢复官方设置”属于原 SLA 配置。通知策略与渠道使用各自的保存按钮，独立调用通知接口，不跟随上方重置。策略未保存时切换分页或关闭编辑会放弃当前输入。没有通过按钮保存的输入不会自动生效。

## 五个分页

| 分页 | 呈现与操作 | 边界 |
| --- | --- | --- |
| 通知策略 | 策略卡片显示事件、状态、版本、渠道、收件人和时间；支持新建、编辑、保存停用草稿及保存启用 | 启用仅影响新事件；已有任务保留原策略版本；停用不取消已有任务 |
| 渠道配置 | 团队与 Lark 群渠道映射，模拟/真实模式，Webhook 变量引用及可选签名变量 | 不输入实际密钥；Email/SMS 未接入，不能选择；改为真实模式会影响引用该渠道的待发送任务 |
| 发送记录 | 最近 200 条任务；按状态筛选，查看事件、客户链接、收件人、计划时间、次数、版本与结果；填写原因取消待发送任务 | 接口接受不等于员工已读；结果未知须人工核查；取消通知不完成跟进任务 |
| 修改审计 | 最近 200 条操作，显示操作人、动作、对象、版本和取消原因 | 当前审计表没有操作时间列，界面不补造时间；历史版本仍在服务端保留，当前没有版本回滚操作 |
| 联调检查 | 显示身份模式、Webhook 是否配置、签名要求是否满足、是否指定测试群 | 不替代真实权限联调和群内实收；实收以验收报告和事件/任务 ID 为证 |

## 策略表单

1. **事件与筛选**：客户登记、聊天更新、重新咨询、请求人工、预约、报名、评测完成、跟进逾期、AI 失败、通知最终失败、每日汇总。来源、客户等级、业务状态和团队筛选支持逗号分隔多个标识，留空表示不限制。
2. **收件人与渠道**：站内提醒可以发给负责人、团队或主管，无负责人时依据规则转团队，接收者必须具备客户数据查看权限。Lark 使用选定群渠道；团队名称并不会自动查找 Lark 群。
3. **发送时间**：立即、延迟、顺延至汇总时间；支持时区、工作日、工作起止时间及跨夜静默时段。站内记录即时生成。每日汇总按指定日期/团队生成，时间预览只预览计划时间，不验证事件匹配或生成汇总统计。
4. **去重、重试与内容**：同类同客户同紧急级别的 Lark 合并窗口、每群每小时上限、暂时失败重试间隔，以及语言与摘要模板。变量为 `{{event}}`、`{{name}}`、`{{owner}}`、`{{due}}`；模板语言影响日期格式，不自动翻译正文。
5. **时间预览**：可指定本机时区的模拟事件时间。调用服务端计算，不保存策略、不创建发送任务、不发送 Lark 消息。

规则保存由服务端验证。不开放任意脚本。新建策略默认仅站内提醒；新建渠道默认模拟模式。若选择 Lark，必须先存在对应渠道。重试只针对明确的暂时失败；HTTP 超时或无法判定的回执记录为结果未知，不盲目重发。

## 发送状态

- 待发送：等待计划时间或工作时间；可取消。
- 发送中：工作进程已领取；不可从界面取消。
- 接口接受：站内记录已写入，或 Lark 成功回执；不是客户跟进完成状态。
- 模拟完成：没有真实对外发送。
- 明确失败：配置或发送错误，可查看结果。
- 结果未知：无法确定外部服务是否已接收，需人工核查。
- 已取消：人工取消、任务已完成或合并去重等原因。
