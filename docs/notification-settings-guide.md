# 通知设置与发送审计

## 页面定位与保存边界

本区域位于 CRM 的 SLA & Policy 下，与现有设置共用圆角卡片、标题图标、浅色/深色主题、分组字段及主色按钮。销售在 Leads 列表处理未读活动、归属和跟进；此区域供拥有 `notifications.manage` 的人员配置通知和排查异常。当前平台适配仍为本地模拟身份，真实主管/管理员角色划分待平台联调。

上方“保存配置 / 恢复官方设置”属于原 SLA 配置。通知策略与渠道使用各自的保存按钮，独立调用通知接口，不跟随上方重置。策略未保存时切换分页或关闭编辑会放弃当前输入。没有通过按钮保存的输入不会自动生效。

## 五个分页

| 分页 | 呈现与操作 | 边界 |
| --- | --- | --- |
| 通知策略 | 策略卡片显示事件、状态、版本、渠道、收件人和时间；支持新建、编辑、保存停用草稿及保存启用 | 启用仅影响新事件；已有任务保留原策略版本；停用不取消已有任务 |
| 渠道配置 | 团队与 Lark 群渠道映射，模拟/真实模式，Webhook 变量引用及可选签名变量 | 不输入实际密钥；Email/SMS 未接入，不能选择；改为真实模式会影响引用该渠道的待发送任务 |
| 发送记录 | 最近 200 条任务；按状态筛选，查看事件、客户链接、收件人、计划时间、次数、版本与结果；填写原因取消待发送任务 | 接口接受不等于员工已读；结果未知须人工核查；取消通知不完成跟进任务 |
| 修改审计 | 最近 200 条操作，显示操作人、动作、对象、版本和取消原因 | 当前审计表没有操作时间列，界面不补造时间；历史版本仍在服务端保留，当前没有版本回滚操作 |
| 联调检查 | 显示身份模式、Webhook 是否配置、签名要求是否满足、是否指定测试群 | 不替代真实权限联调和群内实收；实收以验收报告和事件/任务 ID 为证 |

## 策略表单

1. **事件与筛选**：客户登记、聊天更新、重新咨询、请求人工、预约、报名、评测完成、跟进逾期、AI 失败、通知最终失败、每日汇总。来源、客户等级、业务状态和团队筛选支持逗号分隔多个标识，留空表示不限制。
2. **收件人与渠道**：站内提醒可以发给负责人、团队或主管，无负责人时依据规则转团队，接收者必须具备客户数据查看权限。Lark 使用选定群渠道；团队名称并不会自动查找 Lark 群。
3. **发送时间**：立即、延迟、顺延至汇总时间；支持时区、工作日、工作起止时间及跨夜静默时段。站内记录即时生成。每日汇总按指定日期/团队生成，时间预览只预览计划时间，不验证事件匹配或生成汇总统计。
4. **去重、重试与内容**：同类同客户同紧急级别的 Lark 合并窗口、每群每小时上限、暂时失败重试间隔，以及语言与摘要模板。变量为 `{{event}}`、`{{name}}`、`{{owner}}`、`{{due}}`；模板语言影响日期格式，不自动翻译正文。
5. **时间预览**：可指定本机时区的模拟事件时间。调用服务端计算，不保存策略、不创建发送任务、不发送 Lark 消息。

规则保存由服务端验证。不开放任意脚本。新建策略默认仅站内提醒；新建渠道默认模拟模式。若选择 Lark，必须先存在对应渠道。重试只针对明确的暂时失败；HTTP 超时或无法判定的回执记录为结果未知，不盲目重发。

## 发送状态

- 待发送：等待计划时间或工作时间；可取消。
- 发送中：工作进程已领取；不可从界面取消。
- 接口接受：站内记录已写入，或 Lark 成功回执；不是客户跟进完成状态。
- 模拟完成：没有真实对外发送。
- 明确失败：配置或发送错误，可查看结果。
- 结果未知：无法确定外部服务是否已接收，需人工核查。
- 已取消：人工取消、任务已完成或合并去重等原因。

## 2026-10-12 工作日历与渠道显示修复

发送时间默认继承上方已经保存的全局 SLA 工作日历，只读显示时区、工作日与起止时间摘要。选择“此策略自定义时间”才显示自定义字段；工作起止时间只在 Lark 工作时间限制开启时显示。立即/延迟策略不显示汇总时间；每日汇总事件或“顺延至汇总时间”模式才显示汇总发送时间。普通站内提醒即时产生，纯站内策略不显示外发时间；每日汇总的站内提醒在汇总事件生成后产生。静默时段只适用于 Lark。时间预览不保存、不发送，结果使用策略实际时区显示。

新策略默认继承全局 SLA；历史标准默认日历在读取时按继承处理，历史自定义日历保留自定义，不直接改写数据库。旧排队任务没有日历模式时继续使用原快照日历；新继承任务按全局日历安排并在发送前再次检查。修改日历不重算已有跟进截止时间，也不提前重排已排队通知。

“顺延至汇总时间”是延后单条通知，不能等同于内容统计合并；真正团队统计由 `daily.digest` 事件生成。

Lark 群名称由管理员填写，系统不会根据 `sales` 自动识别实际群。`sales` 是渠道或团队内部标识；界面优先显示群名称、团队名称与状态，未命名时明确显示“未命名群”。状态区分模拟模式、缺少 Webhook、缺少签名密钥、非指定测试群受限、已配置待实收确认。服务端只返回配置检查结果，不返回密钥；“已配置”不等于群内实收。

已修复系统默认策略 ID 含点（如 `lead.created`）时前端保存被拒绝的问题。本次使用新的独立数据库与模拟客户完成验证，没有切换真实 3000 服务；最新测试和证据见 [工作日历与渠道验收报告](notification-calendar-acceptance-20261012.md)。以上说明替代早期策略表单中独立工作日历的描述。

## 五维策略表单与群级限流

当前表单按“触发条件 → 通知对象 → 发送安排 → 消息内容 → 发送保护”组织。

- 客户所属团队是事件适用范围；接收团队是站内通知对象。负责人缺失时的团队明确标为“无负责人时转交团队”。主管通知针对主管团队，不等同于直属主管。
- 仅勾选站内提醒才显示站内收件人与接收团队；仅选择 Lark 才显示群、摘要模板、日期显示语言、重复抑制和重试。纯站内提醒使用自动生成的客户/事件信息。
- “指定时刻发送（逐条通知）”延后每条通知；“每日统计汇总时间”用于 daily.digest 统计事件。两者不宣称合并聊天正文。
- “重复通知抑制窗口”只抑制同群、同客户、同事件、同紧急级别的后续通知，不合并内容，也不影响聊天保存。高级发送保护默认折叠。
- 模板旁提供显式 TEST 数据预览，只替换正文变量，不调用 Lark。“日期显示语言”不翻译模板。
- 每群每小时发送上限统一在渠道配置中保存，群内全部策略共用。0 暂停发送，达到限流时待发任务顺延，不删除。模拟成功也计入模拟环境的频率统计。
- 旧策略 maxPerHour 字段保留，不批量改写；渠道已有显式上限时优先使用渠道值。未设置渠道上限时，采用引用该群的历史策略和任务快照中最严格的有效值；无历史值默认 20。页面显示兼容来源，保存渠道后固定为渠道统一值。

本次验证见 [五维策略与群级限流验收](notification-dimensions-acceptance-20261012.md)。以上取代旧指南中策略内独立限流和“合并窗口”的表述。

## Lark 渠道三分区（最新）

渠道表单按“基本信息、连接配置、发送保护”组织，取代此前的团队字段和始终显示连接字段的设计。

1. 基本信息：渠道名称只用于 CRM 列表、策略选择器和摘要识别，不修改 Lark 群名，也不决定实际发送目标。运行方式为模拟测试或真实发送。
2. 连接配置：模拟模式没有 Webhook/签名输入，服务端也不要求它们。真实模式要求 Webhook 服务端环境变量引用；只有开启签名验证才要求签名密钥引用。禁止在引用字段填写实际 URL/密钥。已有连接信息在切换模拟时保留但不使用；关闭签名时旧引用保留但发送器不使用。连接状态依据保存的配置，接口接受看发送记录，实际群内收到需人工确认。
3. 发送保护：每小时上限由此渠道的所有策略共用，模拟可验证限流；默认 20，0 暂停发送，超限顺延。

团队名称/标识从表单、卡片和群选择器移除；历史值保留兼容，不宣称自动路由。内部渠道 ID 系统生成、只读、折叠显示；重命名显示标签不修改 ID 或策略关联。渠道卡片补充引用策略总数及已启用数。

最新验收见 [Lark 渠道三分区验收报告](lark-channel-settings-acceptance-20261012.md)。
