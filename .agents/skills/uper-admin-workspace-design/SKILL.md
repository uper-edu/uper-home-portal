# 管理工作区设计
环境与验收范围遵循项目 [AGENTS.md](../../../AGENTS.md)：默认只在3000开发和验证；独立环境须先说明原因与范围并获用户明确确认，不能自行先启动。默认只验证中文电脑端；其他语言、三语切换、移动端／窄屏测试仅在用户明确要求后执行。保留三语与响应式设计要求，不将其自动扩大为本轮测试范围；未测项如实报告。

实施前读 [规范](references/design.md)，验收时读 [矩阵](references/acceptance.md)。
1. 先声明主题导航、记录工作、集合管理模式；禁止为统一增加无价值导航。
2. 记录已验收基线和允许清单，不能整体携带脏工作区。
3. 复用登记组件、变量；变体说明用途，不复制近似实现。
4. 区分目录、记录、页签、折叠；只保留一个主标题。
5. 不改变权限、归属、分类、评分、期限和保存事务；跟进策略按主题保存，通知单条和即时字段各自保存，不合并事务。
6. 切换主题保留草稿；离开上下文提示；后台刷新不覆盖输入；结果未知不自动重试。
7. 区分加载、空态、无权限、失败和保存状态。
8. EN/ID/ZH和在线文档同步，用户原文不改。
9. 验证导航、返回、滚动、键盘、草稿和保存，报告未验证项，截图不等于功能测试。
10. Skill不授权3000切换、推送、部署、通知实发或禅道写入。
11. 常规变体依规范执行；模式、权限、保存语义实质变化须重新确认。
样板门槛：先交付三类样板，用户确认后推广。

## 表单字段与保存校验
修改表单须遵循 [字段规范](references/form-fields.md)：字段名＋*；现有表单标题旁“* 必填”，不单独占行；无星号即选填，不重复显示选填标签。星号、条件、无障碍属性和实际保存校验必须一致；必填缺失不得发起保存或更新，不得仅做装饰。保持现有必填规则与保存事务。

## 颜色与权限入口
凡调整颜色、状态、主题、主按钮或权限入口，必须读取[颜色执行规范](../../../docs/design/admin-color-system.md)，复用 `admin-colors.css` 的语义变量，并按验收矩阵核对浅深色配对。来源、AI方式、采用状态、联系结果、销售阶段和联系限制各自表达，不互相推断；未授权扩大业务或验收环境。权限入口复用 `progressActionState` 和 `CrmProgressAction`，隐藏无权操作，认领前置步骤和保存中才禁用。

## 三语交付与紧凑列表
固定界面文案、状态、提示、无障碍名称必须同时有ZH／EN／ID；不能只翻译标题而遗漏动态状态和子说明。原问卷答案、客户对话、姓名、销售自由文本及修正原文保持原样。Lead列表使用独立短标签（Budget／Anggaran、Availability／Jadwal、Start／Mulai、Concerns／Kendala），不缩小字号或改业务口径；表单保留完整名称。列表和跟进页三条时间线共用interactionTrackLabel，不分别维护近义名称。新增固定文案需补充词典完整性及含数据状态测试；实际三语页面验证仅在用户授权后执行。
