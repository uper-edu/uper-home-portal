# 规范与组件
主题型：运营/文档/CMS分类，256px目录，1024px以下临时目录，正文自然滚动。记录型：Lead/Campaign详情，320px列表，1120px以下单视图，保留筛选和位置。集合型：首页/用户/角色/审计，默认不加左栏；CMS可组合。
复用AdminHeader、CrmDetailHeader、CrmDetailTabs、CrmSaveFeedback、CrmDiscardDialog、CrmDisclosure。AdminTopicFrame仅布局，不发请求不判断权限；目录关闭不卸载表单。动态测量页头，鼠标选主题不夺焦点或强制顶端对齐；标题被遮挡才最小滚动，键盘选中可聚焦标题，窄屏收起目录后确保标题可见，返回恢复位置。
正文14px辅助12–13px；间距4/8/12/16/24/32；容器圆角14px控件10px；操作40px触控44px。颜色执行[全局颜色与状态规范](../../../../docs/design/admin-color-system.md)：青绿操作与选中，焦点独立轮廓；红色明确失败／原规则逾期，琥珀待确认／未知，蓝色信息。不得自行以今天到期新增预警。图示默认折叠，配置先于辅助说明。保存条不遮末尾字段。

目录自身滚动位置保留；禁止对每次选择无条件调用scrollIntoView。页面采用统一动态页头高度，避免滚动锚定造成布局跳动。全局策略预设在“更多操作”；日历/SLA模拟和决策图在对应主题的规则解释中；通知主题不显示全局策略工具，不改变保存事务。

目录滚动边界：目录使用overscroll-behavior-y:contain隔离鼠标滚轮和触摸惯性；禁止window/document全局wheel或touchmove拦截。光标位于正文时页面仍正常滚动。键盘滚动键（方向、PageUp/PageDown、Home/End）仅在目录焦点上下文内作用于目录并在边界夹紧；不得抢占输入、下拉、菜单原有键盘行为，也不得拦截Tab、Enter或空格激活。窄屏面板同样适用；Escape返回展开按钮。

保存操作规范：每个编辑对象仅一组操作，位于紧凑标题区；长表单使用所属编辑容器内的sticky标题行，动态页头偏移，不固定整个摘要卡，不另设重复底部保存条。跟进策略按钮统一为保存/Save/Simpan，仅保存当前主题；其他主题草稿保留并在左目录标记；通知策略保留启用/停用草稿两种原动作；渠道独立保存；只读页面不显示保存。状态反馈就近呈现，窄屏允许标题操作换行，不遮末尾字段；字段焦点滚动预留吸顶区。更多操作菜单用局部浮层，不能撑大吸顶区。页面自然滚动时目录外框到达吸顶位置之前可随页面移动，但目录自身scrollTop不随右侧滚动改变；这不等同于固定高度左右独立滚动模式。

滚动模式：Lead/Campaign详情宽度≥1120px，动态页头与24px余量扣除后可用高度≥360px时左右独立；否则自然页面滚动，窄屏单视图。主题页（运营/文档/CMS分类）正文自然页面滚动，左目录吸顶、超高才内部滚动，正文不得另套固定高度滚动窗。
使用adminScroll的containPaneKeys和revealRecord；CSS containment与局部键盘边界处理配合，禁止全局wheel/touchmove拦截。输入/下拉/菜单/页签按键优先。记录定位只能移动所属列表，不用会滚动祖先的scrollIntoView。正文滚动可使目录外框吸顶，但不改变目录内部scrollTop。
通知子主题右侧共用单标题/说明/刷新与对象操作，不嵌套重复外卡/子导航；长路由说明默认折叠。编辑才显示保存头；只读主题不出现保存。不改变启停/保存/权限/通知语义。

按主题保存：服务端在原策略行锁内比较当前主题基准并合并到最新完整配置；跨主题并发可合并，同主题冲突返回最新值供核对，不静默覆盖。失败/结果未知保留输入；响应丢失只读核对，不自动重复写入，相同已保存内容重试不重复写审计。后台配置刷新仅更新无草稿主题，不能重置其他草稿；保存期间继续编辑也须保留。恢复默认限定当前主题并经确认保存；全局预设只准备多主题草稿，逐主题保存。当前实现复用crmPolicyTopics和crmPolicyTopicClient。通知策略/渠道不改此保存链路。

编辑容器例外与统一规则：页面配置的保存沿用紧凑吸顶标题；任务型抽屉和居中编辑弹窗使用固定页头＋单一正文滚动＋固定底部操作，不能同时再添加顶部保存。短备注和短阶段操作保持内联。复杂资料、多字段采用和联系结果修正复用CrmOperationLayer compose；记录进展保留progress变体。关闭统一为带无障碍名称的X图标；背景不可交互、关闭返回触发点。未保存离开确认；结果未知保留请求与输入，先查询结果。原文证据与修正关系必须完整保留，不能用视觉归并改变统计或保存事务。来源核实保留就地证据上下文，按证据→范围→决策→结果组织，典型场景默认折叠。

客户详情操作分组：浏览导航（返回列表、上一位／下一位）与客户业务操作分离；准备联系＋记录进展组成稳定操作组，准备为次操作、记录为主操作，不因不同页签漂移。缺少号码时入口保留并禁用，说明原因；原认领、停止联系、身份及服务端授权限制保留。准备联系抽屉沿用compose正文单滚动、底部单操作区：电话在左，复制＋WhatsApp在右。不得让旧sticky负边距覆盖compose操作区；打开工具不等于联系事实。

联系结果颜色必须基于已记录结果，列表与详情复用CrmContactResult：Connected→绿色（浅色#15803d、深色#86efac）；No Response→低饱和琥珀（#946200、#fcd34d）；Wrong Number→红色（#b91c1c、#fca5a5）；无记录／无已知结果→主题中性灰。只着色结果文字，时间和渠道使用中性色，悬停／聚焦强调链接；来源及依据入口保留交互提示，不对整行或背景上色。始终保留文字，不能依靠颜色独立传意。琥珀色不等于逾期或催办，不触发任务；未知发生时间的小型琥珀时钟与联系结果是两种独立语义，不能混用。颜色由共享变量维护，不按模块复制近似色值。

首次联系倒计时统一复用CrmFirstContactCountdown：小时钟＋轻量状态标签，正常中性青灰、逾期浅红底红字；数字略加粗、等宽数字，不显示秒、不闪烁。与首次要求名称同组，空间不足整枚标签换行。只改变呈现，不改变截止时间、计时精度、刷新频率或权限；不自行新增临近预警阈值。图标aria-hidden，文字和timer语义保留、aria-live=off，查看跟进入口独立。

Lead集合筛选：复用CrmLeadFilters与CrmSingleSelect，常用搜索／负责人／销售阶段／首次联系，高级条件按列表业务分组；已选条件展开时也可见。所有筛选均即时生效，多选时保持弹层及高级面板展开，不设置应用或取消按钮；清空条件保留排序及视图，恢复默认按角色恢复。默认不隐藏需处理范围。联系结果与列表sales时间线同源，意向与worklistIntents同源；不把事实里程碑、阶段与意向混成一类。不得以改名掩盖旧数据字段或未实现的查询能力；已删除选项不歧义映射。详见docs/crm/lead-filters.md。

Lead即时筛选稳定性：桌面高级条件尽量一行，隐藏占高的分组标题及重复规则说明，保留无障碍分组及提示。切换查询不清空已授权列表及刷新时间；保留现有内容至新结果返回，更新状态预留空间，结果容器标记aria-busy。旧请求必须取消隔离；权限撤销、授权变更继续立即清除旧数据，不得以防闪烁为由保留越权内容。

Lead详情侧栏筛选采用收起式工具区：默认搜索＋筛选计数与匹配人数；其余条件、条件标签、排序和恢复默认展开后显示，与首页共用状态及即时查询。展开区为锚定浮层，覆盖列表而不推移列表或详情，限制高度、内部滚动；点击外部或Escape收起，保留选项弹层键盘优先级；收起不清条件、不卸载客户详情及草稿；隐藏控件不能占用键盘Tab顺序。

Lead指标分三层：列表四项客户概况采用紧凑横条；页头“统计与分析”进入独立页面，承载可筛选的七阶段分布、联系与推进分析及口径。分析页继承当前筛选，点击指标下钻返回列表；返回保留筛选与滚动位置，刷新及浏览器历史恢复所在页面，不再在列表堆叠详细分析或使用遮挡列表的浮层。全部跟随当前权限与筛选；销售可用时长和阶段分析，负责人比较按现有经理权限。下钻与统计共用crmLeadAnalytics只读判断，未知时间不补为保存时间，实际联系时长与首次要求处理时效分开。仅consultation首次要求计未完成／逾期，不扩张任务体系。阶段分布不是漏斗；Campaign经营分析保留营销活动中心。口径见docs/crm/lead-overview.md。

客户资料边界：基本资料、当前学习需求、原始依据和业务状态分开；复用CrmProfileEditor与CrmCurrentField，基本资料组“编辑基本资料”，学习需求组“调整学习需求”，支持字段就地进入。当前值不冒充原问卷；AI是处理方式，来源仍是客户对话或销售记录。不同记录按字段展开，预算组合阅读、逐字段依据按需查看。直接编辑保存即明确采用，保留旧值、来源、字段版本和历史，未选字段不变，清空须明确选择；AI不得借人工入口扩大字段范围。跨客户依据拒绝；结果未知查询原操作，不重复写入；失败保留草稿。业务状态独立管理，联系方式不得绕过既有身份校验。参见docs/crm/customer-profile.md。
