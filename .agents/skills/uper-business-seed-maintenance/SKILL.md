# 维护 UPER 经营初值

用[仓库清单](../../../docs/operations/company-test-business-seed.md)查当前登记版本、导入范围和目标环境重配项目。用[初始化手册](../../../docs/operations/manual-database-startup.md)查执行顺序、数据库门禁和恢复方式。首次使用时读项目 [AGENTS.md](../../../AGENTS.md)。

## 确定本次范围

- 仅修正文档时，从当前已登记的私有 SQL 或源库只读核对相关行，仅改有差异的文档。
- 确认经营初值发生变化后，从 local 3000 的 dev 库导出新快照。保留上版 SQL 和校验值。按已确认的业务范围更新课程、班次、教师、CMS、推广及运营配置。账号按独立开户脚本处理，密码和服务凭证在目标环境重配。

## 更新私有 SQL 和仓库清单

1. 从仓库根目录运行既有只读导出器。传入本次核定的公司 test 新库名和一个未使用的私有输出文件。比较普通数据变更时沿用同一个演练库名，以免混入库名变化。

   ```sh
   node --import tsx scripts/prepare-empty-portal-business.mts "$seed_target" "$candidate_sql"
   node .agents/skills/uper-business-seed-maintenance/scripts/compare-snapshots.mjs "$candidate_sql" "$previous_sql"
   ```

2. 逐项核对导出和对照结果。比较器只输出哈希和逐表／分组计数。数量相同也检查内容变更，尤其是班次日期和教师、附件、活跃推广 ID、收款账户、收件范围及投递模式。发现范围外差异时保留原版并列明差异。客户和订单历史、统计导入结果、运行数据和账号凭证均按既定排除范围处理。
3. 给确认的私有包登记唯一版本。记录 UTC 导出时间、完整源码提交号、目标库名、文件 SHA-256、导入时使用的业务摘要和数据计数。保留以前的版本和摘要。仓库清单只放汇总、规则和重配细项。完整 SQL、教师附件、逐人薪酬和收款账号留在权限受限的私有存储。团队共享需要获准的加密版本库，密钥另存。
4. 仅在步骤、导入范围、环境依赖或验收方式变化时更新初始化或凭证手册。区分业务初值与目标环境重新配置的账号、密钥、邮件、Lark、AI、GA4、COS、收款和看板数据。
5. 检查文档、摘要和对照结果。只读导出及文档维护在当前范围内完成。改动导入器、SQL 或导入结构时，按项目规则取得隔离授权后验证空库、同包重跑和失败保护。提交、推送、部署或在实际库执行 SQL 按本次用户授权和项目规则处理。
